# Command inventory

Read-only inventory of the registered CLI surface at baseline d4fe6fa7358f018fd1da0c6b96ec2b022247e898. The inventory used static source inspection; CLI behavior still needs runtime characterization.

## Summary

`src/cli.ts` registers 18 top-level names: 13 command families and five top-level leaves (`completions`, `config`, `schema`, `api`, `markdown`). Recursively counting each registered terminal subcommand once, under its canonical registered name, yields **86 canonical leaves**: auth 7, issue 25, team 7, user 1, project 7, project-update 2, cycle 2, milestone 5, initiative 11, initiative-update 2, label 3, template 2, document 7, top-level leaves 5. Aliases do not increase the count. The root and 19 nonleaf group routes also have executable default actions (20 parent routes total); these are listed separately below. Cliffy-generated help/version/completion-shell options are not counted as source-registered leaves. `auth-status.ts` is exported source but is not registered by `auth.ts`, so `linear auth status` is **not** in the public command tree.

**Alias evidence.** Every alias in the table is a static `.alias()` declaration from `src/cli.ts`, its family registration module, or the leaf command module; no alias was confirmed by running the CLI in this read-only task. The only registration assertions found in `test/main_test.ts` confirm `configure` resolves to the config command and `markdown` is reachable by name; they do not exercise a subprocess or all aliases. `document` declares `doc`/`docs` on its own command object, so root exposure still needs a runtime check. There are 36 static alias declarations in total: 11 root-chain aliases, 5 family-chain aliases (`issue` 3, `initiative` 1, `initiative-update` 1), 2 on the document command object, and 18 leaf-object aliases. Same text at different depths is distinct (`i`, `l`, `v`, `c`, `d`, etc.).

**Executable parent/default routes.** Bare `linear` prints a help hint. Bare `auth`, `issue`, `team`, `user`, `project`, `project-update`, `cycle`, `milestone`, `initiative`, `initiative-update`, `label`, and `template` call `showHelp()`. Bare `document` prints a subcommand hint. Nested `issue comment`, `issue relation`, `issue agent-session`, `project comment`, `initiative comment`, and `document comment` call `showHelp()`. That is 1 root + 13 top-level groups + 6 nested groups = **20 parent actions**. Their output, exit status, aliases, and help behavior deserve direct process-level parity checks.

**Flags and argument semantics needing special attention.** Root `--workspace <slug>` applies globally and conflicts with `LINEAR_API_KEY`; `label list --workspace` is a separate local boolean. `issue mine` has no `--json`, while `issue query` has `-j/--json` and search/filter flags; they are distinct behaviors despite the `list` alias on mine. Query/mine share state, assignee, team/project/cycle/milestone/label, dates, sort, limit, and pager behavior, with different default selection. `--no-*` flags (`--no-pager`, `--no-download`, `--no-comments`, `--no-interactive`, `--no-template`, `--no-use-default-template`) use Cliffy negation semantics. Repeated/collection flags include `api --variable`, issue labels, and project member/team/label/initiative edits; preserve order, multiplicity, and replace versus add/remove behavior. `--bulk`, `--bulk-file`, `--bulk-stdin` and confirm/force variants appear on issue archive/delete, initiative archive/delete, and document delete. `--body-file`, `--description-file`, `--content-file`, and `api --variable key=@file`/`@-` read files/stdin. `comment add` uses `-p, --parent, --reply-to` as one option; issue comment add additionally has `--id`, `--attach`, `--public`. `issue relation` accepts `blocks`, `blocked-by`, `related`, `duplicate`; `blocked-by` reverses the issue order for the GraphQL mutation. `issue agent-session list --status` uses a custom enum parser. `api --paginate` follows a single connection, `--silent` suppresses output but preserves failure status, and `--variables-json` merges beneath repeated `--variable`. `schema --json` changes format and `-o/--output` writes a file. `-w/--web` and `-a/--app` open URLs on applicable list/view routes. `-j/--json` names and output structures vary by command; preserve raw GraphQL field names and connection nesting as specified by `AGENTS.md`.

**Config/environment.** `src/config.ts` loads global TOML from XDG/HOME or Windows APPDATA, then project TOML from cwd and Git root; project config shadows global per option, and environment `LINEAR_<OPTION>` shadows both. It loads `.env` from cwd then Git root, limited to `LINEAR_`, `GH_`, `GITHUB_`, honors `LINEAR_IGNORE_ENV_FILE`, skips dangerous shell expansion/unclosed quoted values with stderr warnings, and tracks path provenance for relative `pr_template`. Options include `team_id`, `api_key`, `workspace`, `issue_sort`, `issue_create_ask_project`, `issue_create_assign_self`, `vcs`, `download_images`, `hyperlink_format`, `attachment_dir`, `auto_download_attachments`, `pr_template`. `resolveIssueSort` and `resolvePrTemplate` reject invalid explicit values; general `getOptionWithSource` currently returns undefined on invalid parse, an observable divergence. `src/utils/graphql.ts` resolves API key from environment, config, or credentials, uses injectable `LINEAR_GRAPHQL_ENDPOINT`, and emits authentication errors. `LINEAR_DEBUG`, `NO_COLOR`, `PAGER`, `EDITOR`, TMPDIR/TMP/TEMP, XDG_CONFIG_HOME/HOME/APPDATA, and GH/GITHUB environment also affect behavior. `test/config.test.ts`, `test/utils/graphql.test.ts`, and `test/utils/errors.test.ts` cover parts, not all startup precedence combinations.

**Credentials/platform.** `src/credentials.ts` loads at import time; `credentials.toml` supports both legacy inline plaintext workspace keys and current default/workspaces metadata with OS keyring entries. Migration, default selection, deletion, cache population, warning/error behavior, and the `--plaintext` login path affect compatibility. `src/keyring/{index,linux,macos,windows}.ts` uses service `linear-cli`; Linux shells out to `secret-tool`/Secret Service, macOS to `/usr/bin/security`, Windows uses native Credential Manager via Deno FFI. `test/keyring.integration.test.ts` runs separately on all three OSes in CI; ordinary CI excludes it. Credentials must not be read during inventory or fixture capture.

**Filesystem/subprocess/network.** `src/utils/{vcs,git,jj,actions}.ts` and issue `start`/`commits`/`describe`/`pull-request` use Git, jj, and gh command processes and current repository state. `src/utils/editor.ts` uses Git-configured editor or `EDITOR` and a temporary Markdown file. `src/utils/pager.ts` uses `PAGER`, OS fallback, TTY/terminal height; `src/utils/hyperlink.ts` and display use TTY and `NO_COLOR`. `src/utils/{markdown-images,upload}.ts` downloads private images and uploads attachments; `document view`, `issue view`, comments, and Markdown conversion have related side effects and `--no-download` controls. `src/commands/{config,schema}.ts` write files; `api` reads stdin/files, sends raw HTTP, and exits explicitly on failures. `src/utils/{linear-url,issue-identifier,prosemirror,templates,comments,linear}.ts` carry URL identity, Markdown/ProseMirror, template resolution, pagination, and output formatting rules. `test/utils/*` covers many helpers, but handler tests frequently import commands directly or use mocks, leaving executable, shell, TTY, help, alias, and OS behavior underrepresented.

**Build/release.** `deno.json` exports `src/main.ts`, version 2.6.0, uses Deno tasks for codegen/check/test/install/compile; GraphQL schema is committed at `graphql/schema.graphql` and generated TS is ignored. `dist-workspace.toml` runs `deno compile --target=$CARGO_DIST_TARGET --allow-all` for five macOS/Linux/Windows targets and cargo-dist 0.31.0; installers are shell/npm/Homebrew, with updater and GitHub publish jobs. `.github/workflows/ci.yaml` pins Deno 2.7.9, runs codegen, format, lint, type check, tests, skill-doc generation, and separate three-OS keyring integration. `.github/workflows/release.yml`, `publish.yaml`, and `.github/build-setup.yml` are additional packaging surfaces. `docs/deno-permissions.md` documents permission synchronization for Deno paths. The Rust port must account for the `linear` binary name, package channels, generated completions/help docs, target-specific keyring behavior, and current version metadata.

## Uncertainties

This is a static registration/source inventory. Runtime characterization must confirm whether Cliffy exposes `document`'s command-local `doc`/`docs` aliases at the root and how it resolves the two `--workspace` definitions. These behaviors have not been verified by invoking the CLI. “Mirror” presence does not establish that each flag, error, output mode, terminal behavior, or GraphQL operation is covered. Cliffy-provided completion shell choices and implicit help/version routes should be captured by a future harness; they are excluded from the 86 source-registered leaf count.
