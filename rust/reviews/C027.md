## Contract and implementation

The action implements `linear project comment list <project> [-j|--json]` through the existing project reference resolver and a typed Cynic `GetProjectComments` query. It selects `project(id:)` for existence and the root `comments` connection filtered by project. The `$id: String!` and `$filterId: ID!` variables carry the same resolved UUID; page one includes `"after": null`. Every page is fetched before one stdout write. A null project or GraphQL not-found from any comment page is translated to `Project not found: <original input>`; resolver misses keep the resolver suggestion, and other GraphQL errors keep the preferred presentable message. Pagination retains duplicate nodes and the final `pageInfo`, accepts an empty next cursor, and gives the comments-specific diagnostic for missing/repeated cursors.

JSON projects only the selected GraphQL fields in source fragment order, with their original names, nesting and nulls. Text rendering sorts roots newest first, direct replies oldest first, then orphan replies oldest first; it preserves stable ties, body/quote line handling, author fallbacks and bold only when `NO_COLOR` is absent. No spinner runs. The console-like stdout policy gives a quiet success for a closed pipe. Production code is in `commands/project_comment_list.rs` (SHA-256 `968a7d147bbd98efea3d6d080215d48625965949d0c63396e1e49a29e797da58`) and `graphql/operations/project_comments.rs` (SHA-256 `38c728e677c0ca1312d11f9b28d1084d14998ae4a08de9b441f5fa4860aee1ad`). No new dependency was added.
