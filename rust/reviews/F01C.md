## Reviewed observations

All 20 proposals had empty file effects and no fixture traffic. Eleven exited 0 with empty stderr; nine exited 2 with colored usage diagnostics, except `NO_COLOR=1` which removed ANSI. Usage failures print the relevant command's help to stdout, then a diagnostic on stderr. `NO_COLOR=""` keeps ANSI in both help and usage errors; `NO_COLOR=1` removes it. F01-A already captured both version color variants.

The parser is order-sensitive: `--help --version` prints root help and exits 0, whereas `--version --help` exits 2 with `Option "--help" cannot be combined with other options.` Both root and issue `--workspace ws --help` produce the same combination error and exit 2. `issue --version` is an unknown option error, confirming version is root-only. Root `--workspace` without a value exits 2 with `Missing value for option "--workspace".` Nested `issue frobnicate` suggests `create`; parent `issue --bogus` suggests `--help`.

The `i` and `docs` aliases give byte-identical outputs to the canonical parent bare/help cases. `issue list` and `issue l` help are byte-identical to the existing `help-issue-mine` anchor. `issue q` resolves to canonical `linear issue query`. `configure --help` resolves to canonical `linear config` without running its interactive action.
