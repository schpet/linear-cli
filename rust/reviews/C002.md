## Implementation

`DispatchAction::AuthList` replaces the unimplemented `AuthListR4` mapping in the route generator and generated clap tree. `commands/auth_list.rs` classifies the R02C2 `CredentialStore` without workspace selection. Every listed workspace keeps store order and its default marker. A missing, keyring-miss or failed-lookup key becomes `missing credentials`. A key that `auth::header::to_api_key` rejects becomes `invalid API key`. Only usable keys are prepared. `LINEAR_API_KEY`, sourced `api_key` and `--workspace` do not participate, and the command never rereads the environment, files or keyring.

The ambient R02B4 transport policy resolves once, and only when at least one key is usable. Every `GraphQlTransport` is then built in source order before any request task starts. A policy or build failure is one fatal pre-request `Failed to list workspaces` error. A store with only missing or unusable keys never resolves the policy. `fetch_with` spawns every request into a `tokio::task::JoinSet` with its row index, with no concurrency cap, and places each result back in its row. A join failure, duplicate completion, out-of-range index or unfinished row is a fatal `Invariant`. Request and decode failures stay in their row, so an all-error table exits 0.

The Cynic `AuthListViewer` operation has the frozen name, no variables, and selects `viewer { name email organization { name urlKey } }`. `urlKey` is decoded but not printed, as in Deno. Row text is typed:
- HTTP 401/403 from any response-bearing failure (GraphQL, HTTP or over-cap) is `invalid credentials`.
- A GraphQL error shows the first error's nonempty `userPresentableMessage`, falling back to its `message`.
- The remaining failures use short stable R02B4 transport text.

The renderer sums per-code-point `unicode-width` widths, counting controls and joiners as zero. It pads `WORKSPACE` to at least 9 cells and `ORG NAME` to at least 8, and keeps trailing pad spaces on error rows. When stdout is a terminal and `NO_COLOR` is unset or empty, it emits Deno's console `%c` bytes. The table is written as one buffer through `OutputPolicy::ConsoleLike`.

The prior session's contradiction check found one plan error. The plan assumed that per-char `unicode-width` equals Deno's width table. An exhaustive diff over all 1,112,064 scalar values shows that `@std/cli` 1.0.28 (Unicode 15.0.0) and `unicode-width 0.2.2` differ at 4,388 code points (3,992 1→0, 361 1→2, 29 0→1, 5 2→0, 1 1→3), for example U+4DC0 hexagrams. The existing dependency is kept, and the difference is bound to `C002-WIDTH-TABLE`. Every width-plan string (CJK, combining mark, `❤️`, ZWJ family, `ﻻ`/`لا`, tab, ESC, fullwidth) matches exactly.
