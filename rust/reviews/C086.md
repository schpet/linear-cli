## Frozen protocol observations

`completions complete <action> [command...]` walks command words with Cliffy's `getCommand(name, false)`. A word matches a name or alias, and a hidden match yields no command. It then reads the local completion, then an ancestor's global completion. Only types with `values`/`complete` register completions. Cliffy's main command registers global built-ins `string`, `number`, `integer`, `boolean` and `file`, but only `boolean` completes (`true`, `false`). It does so at any depth, including below the `noGlobals` completions route. Output is `values.join("\n")` through `writeSync`, with no trailing newline and no write when empty. An unknown action is empty with exit 0.

An unknown command word raises `Auto-completion failed. Unknown command "<word>".` followed by a space and `Did you mean command "<visible name>"?` when the parent has visible commands. This happens as an uncaught error: exit 1 with a stack trace. The hidden `complete` route resolves nowhere, and its suggestion is `bash`. Words after `--` are literal and select nothing. `noGlobals` rejects `--workspace` after `completions`, but a root `--workspace` before `completions` is consumed and ignored. Scripts are printed through `console.log`: closed stdout is quiet with exit 0, and `complete` on a closed pipe dies with an uncaught `BrokenPipe`. A malformed credentials file is fatal at import, before either action. Cliffy emits `--name` verbatim, so `-foo` and shell metacharacters produce broken or injectable scripts. The v2 bash script alone calls hidden `complete` at 371 value positions. Cliffy's bash and fish scripts neither navigate nor offer aliases, and its zsh navigates but does not offer them. The v2 bash defines `__linear_project_update()` twice, and v2 fish lists `__linear_project_update` twice, so hyphen/space collisions predate v3.

## Rust implementation

- **Clap metadata** (`cli/clap_tree.rs`): route aliases are now `visible_alias`. Secondary option spellings (`--ref`, `--reply-to`, the only multi-long options) are `visible_alias`/`visible_short_alias` because Cliffy lists them and v2 bash offered them. Every workspace, switch, valued, collected and bulk argument has `.help(option.description)`, and help/version arguments use shared `HELP_FLAG_DESCRIPTION`/`VERSION_FLAG_DESCRIPTION` constants. The help renderer now reads the same constants, with byte-identical text.
- **Completion projection:** the builder takes a private `Surface`. `build()` is the unchanged `Parse` tree. `build_completion()` uses the same inventory and builder, but omits hidden routes and hidden options, omits `internal:surplus`/`internal:literal`, uses plain argument names as positional ids and uses each description's first line as `about`. `clap_complete` ignores `hide` entirely, and zsh puts positional ids with colons directly into `_arguments` specs. Correcting the builder metadata here is the plan's "correct the clap metadata first" route. No script text is post-processed.
- **Routing:** `rust/tools/generate_routes.py` maps the five completion routes to `Completions`, `CompletionsBash`, `CompletionsFish`, `CompletionsZsh` and `CompletionsComplete`. `generated.rs` was regenerated, and `--check` passes.
- **Command** (`commands/completions.rs`, `app.rs`):
  - The bare parent prints its help with `OutputPolicy::ConsoleLike`.
  - Shell children generate into a `Vec<u8>` and write with `ConsoleLike`. Bash and zsh use `generate(Shell::*, build_completion(), name, &mut buf)`; fish uses `cli::fish_completion::script(build_completion(), name)`. The default name is the literal `linear`. `--name` must match `[A-Za-z0-9_][A-Za-z0-9_.-]*`, otherwise a handled `Invalid command name` validation error is raised before generation.
  - Hidden `complete` walks the production clap tree by name or alias and rejects hidden commands with the existing `suggest::closest` wording. It then resolves the typed unique route and looks up its generated local type, then ancestors' global types, then the built-in `boolean`. `TypeHandler::Variable` and unregistered types are empty. Output is LF-joined without a trailing newline and uses `OutputPolicy::Strict`, with no write when empty.
  - Startup still runs before parsing for every completions route.
- **Fish generator** (`cli/fish_completion.rs`): a typed generator over the same built `build_completion()` `Command`. It does not implement `clap_complete::Generator`, because that trait cannot return the generator's invariant errors, and it never touches another generator's text. The script has four helpers named from the bin name (`-` and `.` become `_`):
  - `__fish_linear_subcommand PATH WORD` is a `switch` over `"PATH:WORD"` for every parent, child name and visible alias. It prints the child's canonical path, such as `linear issue comment update`.
  - `__fish_linear_takes_value PATH SPELLING` lists valued option spellings at every command path, including leaves. Parent options must take exactly one value; a leaf may also have a multi-valued option.
  - `__fish_linear_command_path` walks `commandline -opc` from the root. Under a parent, the word after a valued option is skipped, `--opt=value` is one word, and short clusters take the rest of the word or the next word. Any other word must be a child name or alias. An unknown word under a parent, or `--` anywhere, fails, so nothing from the tree is offered. Under a leaf, words are positionals and no longer navigate.
  - `__fish_linear_using_command PATH` compares the walked path with one exact path. Every `complete` entry asks, so the walk is cached in two globals keyed by the `string escape`d word list. That brought a depth-three TAB from about 220 ms to about 60 ms under fish 3.7.0 on this VM. Each visible command gets `-f` when it has no positionals, one line per option (all short and long spellings, `-d`, `-r`, and `-f -a` enum values with empty `\t''` descriptions), and one `-a` line per child name and alias with its first description line. The generator rejects trees it cannot model: hidden commands, options or values; a parent with positionals or a multi-valued option; undescribed options or commands; names, flags or values outside `[A-Za-z0-9][A-Za-z0-9_.-]*`, which it embeds in `switch` patterns and `-a` lists; and a bin name outside `[A-Za-z0-9_][A-Za-z0-9_.-]*`. It uses no external commands, so it works with an empty `PATH`.

## Reviewed v3 differences

1. **Scripts:** bash and zsh are `clap_complete` output and fish is the project generator's output, not Cliffy's. They have a different structure and no `v2.6.0` header. Enum values are embedded, so a TAB no longer runs the CLI with its startup. All three shells now navigate and offer the 36 route aliases and the secondary spellings. Hidden options and the hidden `complete` route stay absent. Fish completes every visible route's options and values at every depth. It completes command words only under the exact parent the line selects, and stops after `--` or an unknown command word. Fish still falls back to its default file completion when no entry applies. That happens after `--`, after an unknown word, for positionals and for untyped option values such as `--body-file`. v2 fish offered no files, because every Cliffy entry was `-f`.
2. **`--name`:** a name outside `[A-Za-z0-9_][A-Za-z0-9_.-]*` fails with exit 1: `✗ Invalid command name "<name>"` plus a suggestion line. Frozen Deno emitted such names unescaped, producing broken or injectable scripts. This affects `c086-bash-hyphen-name` and `c086-bash-metachar-name`.
3. **Hidden `complete` failures:** unknown words fail as handled `✗ Auto-completion failed. …` with exit 1 instead of an uncaught stack trace with exit 1. A closed stdout gives `✗ failed to write stdout` with exit 1 instead of an uncaught `BrokenPipe`.
4. **Startup:** startup diagnostics use the already reviewed R02C2 Rust credential wording.
5. **Zsh help:** Clap-based help omits Cliffy's `(Default: "linear")` on `--name` and uses shorter padding on the help row; the default script name remains `linear`. This is bound only in `c086-zsh-help` as `C086-CLAP-HELP`.

## Generator deviations

- **C086-BASH-HYPHEN-COLLISION:** `clap_complete` bash uses one separator for `-` and a subcommand boundary. As a result, `project update` and `project-update`, and `initiative update` and `initiative-update`, share a `case` label, and bash takes the first arm. Completing after `linear project update` (or `initiative update`) therefore offers the hyphenated command's subcommands and options. No clap metadata fix exists, because the label is derived from command names. The contract test pins exactly these two collisions and both arms' word sets, and fails if they change. The v2 scripts had the same collision class.
- **C086-FISH-DEPTH and C086-FISH-SEEN (resolved in stage 2):** `clap_complete` 4.6.11 fish returns before third-level commands (`_ => return` for three or more parent words). Its depth-two conditions use `__fish_seen_subcommand_from`, which matches a word anywhere on the line. The stage-2 negative control confirmed both in real fish 3.7.0 against the stage-1 script. The project generator replaces that script, and the real-fish tests above bind the fixed behavior: all 15 depth-three routes, including `--reply-to`, and exact-path selection.
