# P04A2 review record: helper-owned stdout pipe closure

P04A2 adds `closed-at-start` and `close-after-bytes(N)` to the Linux confined parity lane. The helper owns the target's private stdout pipe and authenticates its closure result; legacy byte expectations still use the direct-drain path. This is a harness capability, not a Rust candidate route-parity claim. No root CLI, SDL, root lock, P03 fixture, candidate Rust, Docker, live Linear, host credential or external-network path was changed or used.

## Contract and boundaries

A fixed runner-only helper argv prefix now carries mode/count before target path/argv. The target receives its original argv, environment, cwd, stdin, stderr, signal disposition and umask. The helper creates the private pipe after HELLO/ACK and before fork, closes its own write copy immediately after fork, and either closes its read copy before target startup or relays exactly N raw bytes before closing it. It still reads the CLOEXEC exec-error pipe, services stdout before `waitpid`, reports an `exec-failed` harness error without closure fields, and authenticates the exact target code or signal through the status socket. The parent ignores SIGPIPE only after fork while relaying; its own EPIPE after a runner stop cannot be mistaken for target SIGPIPE.

`parity-status/2` adds strict mode, count, relayed-byte count and closure token to successful RESULT frames. Drain is `none`, closed-at-start is `before-start`, and after-N is `after-N` or `threshold-not-reached`; malformed, contradictory, wrong-mode/count, old-version, duplicate and late frames fail closed. The maximum grammar frame fits the retained 256-byte bound (tested), and both C and TypeScript keep the same cap. Exact bytes, closure, target exit, stderr, fixture interactions and file effects are separately checked. A matching prefix with threshold-not-reached fails on stdout. A closed-at-start case asserts zero relayed bytes; neither that nor after-N alone proves a target write or EPIPE. Native default-SIGPIPE and ignored-SIGPIPE writers supply that proof in focused tests.

Legacy stdout `{utf8}`/`{base64}` remains exact direct drain. New strict stdout variants are `{"mode":"closed-at-start"}` and `{"mode":"close-after-bytes","count":4,"prefix":{"utf8":"abcd"}}`. The latter requires a literal prefix of exactly N decoded bytes, with N positive and within both declared and effective output cap. Runtime cap override failure occurs before sandbox creation. A base64 prefix may split UTF-8. Reports and proposals carry authenticated `stdoutClosure`; proposals preserve pipe mode and helper provenance. Invalid threshold-not-reached observations cannot become a loadable proposed after-N case.

The native default-SIGPIPE loop writer yields authenticated SIGPIPE and outer 141 in both modes. An ignored-SIGPIPE writer exits code 77 after EPIPE. A two-byte short writer reports threshold-not-reached; the public case comparator reports stdout mismatch. A test-only helper altered to **continue draining** after N does not produce target SIGPIPE or a closure before the engine deadline for an infinite writer, leaving null target status. With a finite writer it can eventually claim after-N without having closed at N, but a case requiring target SIGPIPE still fails on authenticated target code 0; helper closure alone is never target EPIPE proof. A Deno `console.log` loop with stdout closed at startup also reaches the deadline; no target status is invented. Target stderr remains captured after stdout closure. Preflight independently lists the three namespace PIDs in direct-drain mode. Pipe-mode canaries use the helper-authenticated PID 2/3 status and target-reported FD1 readlinks to prove distinct target/helper pipe inodes; their fd-set assertion bounds inherited descriptors but does not independently identify fd 3 by readlink.

The 17 existing A1 controls remain caught. Three new `self-check` mismatch controls are `pipe-prefix-first-byte`, `pipe-threshold-not-reached`, and `pipe-stderr-lost-after-close`. Strict schema errors, cap override, faulty-helper and status-corruption harness errors stay in focused tests because `self-check` represents only candidate fail/not-implemented outcomes. The self-check matcher accepts a control when its intended mismatch surfaces are present; it does not reject additional future surfaces.
