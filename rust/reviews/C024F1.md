# C024F1 — reusable terminal selector

This foundation adds a searchable stdout selector for the future `project view` picker. It does not register a route, fetch GraphQL data, or claim C024 action parity. The selector separates display labels from stable values, supports ANSI-stripped case-insensitive search, Levenshtein ranking, arrow navigation, explicit Ctrl-C and EOF outcomes, and a typed CI/TTY gate. It replaces display control characters with spaces, clips redraw frames by measured terminal columns, and caps rows below the terminal height so long or unusual labels do not corrupt repaint accounting. Input errors and write failures are explicit. Prompt writes use the strict output policy: after stdout fails, continuing to read keys would leave an unusable interactive prompt; the action will map that error. The source-proven dotenv parser admits only `LINEAR_`, `GH_` and `GITHUB_` keys, so `CI` is captured only from the process environment, including a present-empty value.

It also identified `console`'s between-key cooked-mode interval, height overflow and tiny-terminal error classification. The revised renderer normalizes control characters, and a Unix RAII guard keeps stdin raw for the entire prompt, restoring the original termios state on success or failure. The guard preserves output newline translation; Windows remains on `console`'s own key handling pending platform qualification. `console = "=0.16.6"` is pinned with only `std`, because its safe `Term::read_key_raw` works with fd 0 and fd 1 in the no-controlling-terminal PTY used by frozen C024 evidence. The direct Unix `rustix = "=1.1.5"` dependency enables only `std` and `termios`; that crate was already in Cargo.lock via `terminal_size`. `dialoguer` would impose a different fuzzy UI and stderr default, while `crossterm` would require more manual input handling.
