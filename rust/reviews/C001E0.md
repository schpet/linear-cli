# C001E0 — frozen `auth whoami` oracle foundation

This is an evidence slice for the first Rust GraphQL leaf command, not an implementation of that command. Ten cases and one synthetic two-workspace credential fixture live in `rust/parity/runner/c001-frozen-cases/`, separate from the main Rust candidate corpus until C001 can pass them with reviewed v3 goldens. The frozen Deno source is `d4fe6fa7358f018fd1da0c6b96ec2b022247e898`; the pinned compiled reference binary SHA-256 is `a17675c5ab9a0bf5f32f65e5e68112676576972a9979f5a97bc844f6b23e0835`. No host credential, keyring, external network, or live Linear workspace was used. No dependency or lockfile changed.

The cases pin the exact `AuthStatus` GraphQL document and fake authorization/User-Agent for raw environment, inline default, and explicit workspace selection before and after the route. They cover the standard identity text, equal display name and admin-over-guest priority, guest-only role, a GraphQL error that wins over valid partial data, missing all keys, raw-key/CLI-workspace conflict, and an unknown explicit workspace that must not fall back to the default. The three early failures use an unreachable loopback endpoint; a request would change their exact stderr, so zero-request behavior is currently indirect. The GraphQL fixture format requires at least one scripted interaction and cannot represent a zero-request GraphQL server. Later C001 work adds config/dotenv/keyring sources, further errors, candidate goldens and public-binary QA.
