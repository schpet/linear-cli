## Contract and implementation

The [R01B microplan](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B-plan.md) received Claude SHIP before this slice began. R01B1 adds the manifest's 66 positional descriptors, 122 zero-value local switches, one root credential-workspace flag and its 103 inherited representations to the shadow clap tree. The sole intentional manifest exception is `label list`: the local Boolean filter becomes `--workspace-only` while `--workspace <slug>` becomes available there for credential selection. `rust/compatibility.md` records old/new examples and the pending Rust-side help/diagnostic golden. The five completion nodes receive no inherited flag; a root-level workspace selector before `completions` remains valid.

Internal clap IDs are namespaced as `pos:<name>`, `opt:<name>` and `global:workspace`, so positional workspace arguments in `auth logout`/`auth default` remain distinct from credential selection. Registered `--no-*` switches remain independent positive flags. Alternate spellings share one canonical switch ID and repeated non-collect switches are rejected. A shadow-only resolver collects workspace values from each parsed command level and returns a usage error if more than one is supplied; root+leaf and parent+leaf duplicate cases are tested. Valued route-local options remain pending R01B2/B3; this slice does not claim their coverage.

The `label list` spelling override validates the source descriptor's name, single old spelling, zero values, visibility and required status before registration; missing or duplicate descriptors are invariant errors. A final focused test checks the bare `--workspace` has clap `InvalidValue` (missing slug), and same-level repeated global selectors fail. These are shadow parser outcomes. Rendered help/error bytes remain deliberately deferred to R01H's reviewed goldens and R01C's runtime cutover.

The pinned existing clap dependency gained the `string` feature because clap gates `Arg::new(String)` and dynamic namespaced IDs behind it. The lockfile introduced no new package or upgrade. No other dependency was added.
