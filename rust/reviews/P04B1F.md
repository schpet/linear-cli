# P04B1F review record: exclude NUL and lone ESC keys

P04B1's `one_key_event()` accepted canonical `ACTION 0 raw 00` and `ACTION 0 raw 1b` because its one-byte branch accepted every byte below 0x80. This follow-up makes that branch accept exactly `01–1a` and `1c–7f`. A lone ESC is incomplete; ESC remains valid in the seven supported cursor/delete sequences. The C header states the rule. The `/2` pipe branch, `/3` frame grammar, exit codes and all multi-byte validation branches are unchanged. Only the C source, its builder source digest, the native canary and this record are changed. B2B owns the shared TypeScript/C golden-vector test and case JSON.

The complete C behavior/comment diff is two added header lines and this replacement in `one_key_event()`:

```diff
  * Helper stdin accepts canonical `ACTION <index> raw|cooked <key-hex>\n` lines.
+ * A one-byte key is non-NUL, non-ESC ASCII/control (01-1a or 1c-7f);
+ * ESC is accepted only as part of a supported cursor/delete sequence.
-  if (length == 1) return key[0] < 0x80;
+  if (length == 1) return (key[0] >= 0x01 && key[0] <= 0x1a) ||
+                          (key[0] >= 0x1c && key[0] <= 0x7f);
```

The native canary stages and verifies the changed helper, then runs every new control inside Bubblewrap. Each key uses a fresh living target that first enters raw mode and prints `READY`. For `00` and `1b`, canonical ACTION 0 causes helper exit 122 with `not one key event` on helper stderr. The merged transcript is exactly `READY\r\n`, so there is no key echo or target handler output; the status socket reaches EOF without APPLIED, RESULT or DONE. For `01`, `1c`, `7f` and `1b5b41`, each separate session authenticates APPLIED 0 at byte offset 7, the target reads exactly that byte sequence, then RESULT, DONE and clean status EOF follow. The existing size, tty topology, termios, signal, key-gate, closure and cleanup canaries also pass.
