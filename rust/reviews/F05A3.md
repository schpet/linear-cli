# F05A3 — reader-less stdout BrokenPipe policy

Base: committed P04A2 `63ef13f1`, with an empty undescribed jj `@` before edits; integrated parent: local F02 `rust-port` `6316364f`, rebased cleanly. This slice adds a per-operation `Strict` versus `ConsoleLike` output policy and accepts the bare root action's reader-less stdout pipe behavior. It does not implement the `api` route or claim its plain/paginated pipe cases.

`Output::write_with_policy` and `flush_with_policy` return `Written` or `QuietBrokenPipe`. The latter is possible only for a typed stdout `io::ErrorKind::BrokenPipe` under `ConsoleLike`; strict callers retain the `OutputFailure` source chain, including stream, write/flush operation and underlying `io::Error`. `AppContext` keeps the outcome of its latest stdout write for finalization, consumes it at the final flush, and clears it before an independent run or write. Only a root write that actually returned `QuietBrokenPipe` permits its matching final-flush BrokenPipe to be quiet. A successful root write followed by a final-flush BrokenPipe remains a typed failure because the pinned oracle does not prove that sequence should succeed. The root action is the only console-like caller. Stderr, non-BrokenPipe IO, route errors and status observer errors keep the A1 failure path and one diagnostic attempt. There is no global SIGPIPE disposition or process-wide EPIPE handler.

The pinned P04A2 record authenticates the helper's `parity-status/2` target exit and closure separately. Its compiled bare-root closed-at-start case exits 0 with no stdout/stderr; the compiled version after-four case exits 0 with the exact four-byte ANSI prefix. The version prefix alone does not prove an EPIPE and version remains strict. P04A2's native controls distinguish target SIGPIPE from ignored-SIGPIPE EPIPE, detect a helper that keeps draining, retain stderr after closure and reject a threshold not reached. Its integrated confined replay passed 125/125 oracle cases and 20/20 negative controls with no drift; the report SHA-256 is `8dcab684d6e9c0f55cd190865642e400d5e3b7c1ee60c81fcd0a5bdc39b72c0f`.

The registered public `broken_pipe` module exercises first-write and partial-write EPIPE, in-operation flush EPIPE, write-success/final-flush EPIPE, strict write/flush typed errors, non-EPIPE and stderr errors, diagnostic count and a later strict operation after a quiet root action. The existing A1 `output` tests continue to cover ordinary precedence and bootstrap behavior. Bare root closed-at-start is the only reader-less root acceptance case currently frozen; version after-four proves a prefix and exit, while help and parent-help reader-less pipe cases remain pending.
