# P03C2 review record: fixed-host HTTPS downloads

This slice adds two declared fixed-host GET origins to the P03C1 asset fixture. A case may set `fixedHost` to exactly `uploads.linear.app` or `public.linear.app` on a GET asset step. Absent `fixedHost` retains the loopback listener. Fixed-host redirects are safe origin-relative paths to the immediately next same-host step. The loader rejects fixed-host transport environment supplied by a case and requires every fixed-host URL embedded in a GraphQL response to have a declared asset interaction. The C1 scheduler, exact asset matcher, response writer, request counter, and fixture issue path are shared by both entries. No Linear SDL, root dependency, or isolated lockfile changed.

The relay listens only on loopback. It accepts bounded HTTP/1.1 CONNECT headers for a declared host on port 443, creates only an internal loopback TCP connection to the test TLS listener, and records the relay-local ephemeral port with that host before returning 200. The TLS handler requires this mapping for every request, checks the effective request authority and any Host header against it, and passes the verified host to the shared matcher. It never resolves or forwards to the named host. The child receives runner-owned `HTTPS_PROXY`, `NO_PROXY`, `DENO_CERT`, and `SSL_CERT_FILE`; `HTTP_PROXY` is not supplied. The checked CA is copied into each fresh case root before the before-tree hash, so its unchanged bytes are asserted by file-effect comparison. The proxy, TLS listener, and active tunnels stop in `finally`.
