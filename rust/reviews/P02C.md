# P02C — cache the pinned GraphQL schema during case loading

The parity loader previously re-read and re-hashed the 1.16 MB pinned schema, re-read the baseline, and rebuilt the GraphQL schema for each GraphQL case. With 486 non-C002 GraphQL cases in the current main corpus, the P02 loader test took minutes and made the full parity suite impractical on the two-vCPU box. The user and box monitor identified this repeated work. This item keeps one lazy schema context per `loadCases()` invocation and shares it with both baseline and reviewed-candidate fixture checks. Every GraphQL case still compares its own schema digest to the pinned baseline before using the schema. A fresh `loadCases()` call reloads cases, goldens, schema and baseline; non-GraphQL corpora never read the schema. No dependency was added.

The warmed-context regression feeds a valid `a.json` followed by a wrong-digest `b.json` and requires the exact error naming `b.json`.
