# P01 — frozen Deno reference and runtime inventory

Reference: `d4fe6fa7358f018fd1da0c6b96ec2b022247e898`, Deno 2.7.9 on `x86_64-unknown-linux-gnu`. The reference workspace parent (`@-`) was checked against that revision. `baseline.json` pins SHA-256 values for `deno.lock`, `graphql/schema.graphql`, and the compiled `src/main.ts` binary. Two local builds of that binary produced the same SHA-256, `a17675c5ab9a0bf5f32f65e5e68112676576972a9979f5a97bc844f6b23e0835`.

The runtime exporter imports `src/cli.ts` in a child Deno process from a fresh cwd outside the repository. The child has an empty inherited environment, synthetic HOME/XDG/APPDATA, `LINEAR_IGNORE_ENV_FILE=1`, a loopback GraphQL endpoint, and Deno network/process/FFI denial. It traverses Cliffy's public command and option getters. The checked manifest has 110 routes: 86 source leaves, 20 parent routes, and four generated completion children. All 36 aliases resolve from their parent. Local and inherited global options are recorded separately, including the root `--workspace` and `label list` local `--workspace` definitions. Source file and work-item IDs come from the C001–C086 table in `rust/WORK_ITEMS.md`; shared source files are marked. Manifest comparison rejects changed/missing/new routes, aliases, options, source mappings, or baseline identity. Mutable fixture/QA/live status fields are independently required but excluded from runtime drift comparison so later work items can update them.

The exporter also records public Cliffy custom type registrations and their help values, including the `sort`, `template-type`, and agent-session status enums. Function handlers without `values()` are marked `not_available`; non-scalar or asynchronous values are explicitly unknown. Public usage, examples, and registered environment-variable getters are captured for each route. The verifier checks that the reference workspace `@` is empty and its `@-` is the pinned revision. It also requires an empty `jj diff` from that revision to the implementation `@` for `src`, `deno.lock`, and `graphql`, and (since P02) a structural comparison of root `deno.json` with the frozen file that permits only the reviewed `parity`/`parity:test` tasks and `test.exclude: ["rust/"]`. Those checks bind the interpreted exporter to the frozen source used for the compiled binary even though P01's parity files live on the evolving Rust branch.

The verifier takes two external paths, keeping machine paths out of `baseline.json`:

```sh
deno run --cached-only --allow-read --allow-write=/tmp --allow-run --allow-env --deny-net --deny-ffi rust/parity/verify.ts <reference-workspace> <reference-binary>
```

Eight safe help/version probes run against the pinned compiled binary with synthetic cwd and environment. Probe-sourced lazy help/version behavior is identified in the manifest. Parent bare-route actions and parser resolution of the `--workspace` collision remain `pending_safe_fixture` for P02/P07. These are behavior gaps, not gaps in route or option registration inventory. The compiled binary's safe probes use a loopback endpoint and no credentials; P02 will add the authoritative network namespace capture lane. `refresh.ts` is only for regenerating the initial runtime contract and resets coverage statuses to `pending`; later coverage changes should be edited without rerunning it.
