# F06-PAGE-EMPTY — typed empty-cursor pagination policy

`user list` and `team members` have a Deno behavior that sends `after:""` when a page reports `hasNextPage` with an empty `endCursor`. The shared Rust paginator rejected that before making the next request, so C015's frozen two-request case could not pass the exact fixture gate. This foundation adds an explicit `EmptyCursorPolicy` and `paginate_with_policy` without changing existing `paginate` callers. `Reject` remains the default for `team list`; `Allow` sends the first occurrence of `""` on any page, while null and any repeated or previously seen cursor still fail atomically.

The source diff is confined to `graphql/pagination.rs` and its public contract tests; the compatibility note documents the policy. After rebasing onto integrated F07-WIDTH, stale C011E0 and C016 plan-status lines in `RIIR_STATE.md` were refreshed at the coordinator's request. Tests pin the existing `paginate` wrapper's direct empty-cursor rejection, `None` on page one, `Some("")` on the next request under Allow, empty cursors on later pages, repeated empty and `"" → A → ""` cycle rejection, null rejection, and ordinary cycle rejection. Command-specific error wording and GraphQL variable serialization belong to C015/C010, which consume the API after this item. No dependency, runner, Deno, command, fixture, or manifest behavior changes here.
