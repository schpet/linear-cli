# F06-TEAMREF-A: pure Linear URL and workspace reference layer

The Rust `refs` module classifies Linear URLs into typed issue, project, document, initiative, team and cycle references. `expect_team_url` returns the prepared team key for a later resolver, returns `None` for ordinary text, or returns an uncontextualized validation error for an unsupported, foreign-workspace or wrong-kind URL. This change performs no GraphQL lookup, credential selection, command dispatch, member rendering or network access. B and C010 remain responsible for the request and public command parity.

The classifier follows frozen Deno `src/utils/linear-url.ts` SHA-256 `a64eb8e7ecbfe05b5bf030b817df6d89cd060b145bfdcfcf255a6e47b50cb5f5` and `src/utils/issue-identifier.ts` SHA-256 `63edfbc5682475d3ef74dae2309cd7301ef0f351c99eab1d37e26f61328afa1e` for ASCII issue IDs. It uses the existing `reqwest` 0.12.28 URL type (`url` 2.5.8 transitively) and no new dependency. It keeps the original URL in errors, applies WHATWG path normalization before strict per-segment percent decoding, retains encoded slashes within one segment, and checks the current workspace before rejecting a known URL of the wrong kind. The workspace scope borrows the CLI, sourced and stored-default slug plus the existing `ApiKeyInput` provenance; nullish selection and JavaScript whitespace trimming happen independently of later credential selection. The two pre-existing JavaScript whitespace predicates in config and Linux keyring now use one crate-private helper with the same character set.

The public test target loads E0 JSON with `include_str!` and compares prepared URL references to the frozen first `ResolveTeam` request variable. It also extracts the resolver message and suggestion from the public `team members` stderr by removing its exact prefix and terminal LF, then splitting on LF plus two spaces. Exact errors are asserted for `f06e0-malformed-escape`, `suggest-plain`, `suggest-raw-empty`, `foreign-before-key` and additional URL refusal rows; the corrected `workspace-empty-config` asserts success despite a conflicting stored default. URL success rows assert the first `ResolveTeam` variable. The test source cites 31 full E0 case hashes beside its assertions; a static check found all 31 in E0's manifest, whose own test pins the 55-file bundle; A does not rewrite that bundle. The cited URL rows reconstruct their recorded CLI, config/default and raw/sourced-key provenance. The extraction reproduces E0's SHA-256 for the unsupported suggestion `Pass a team URL, key, name, or ID.` (`ca4086d64a66e7c63d12ef543ec6152b9ae10afd8fd6d7317e37fc1751b8a033`) and the `suggest-plain` workspace message (`7eb9737762ab8be41da9204a61a1d5daa29a2e993e90cc34377eca0ea57af166`). Other pure tests cover all six kinds, uppercase slug IDs, Unicode team/workspace case mapping, JS whitespace, anchors, subpages, ports, userinfo, cycles and error order. These extra parser assertions are source-backed; E0 proves only the named public carrier rows.

One deliberate difference is recorded in `rust/compatibility.md`: Deno's plain-object cycle alias table classifies `constructor` as a known cycle through inheritance, whereas the Rust typed classifier rejects it as unsupported. No E0 case proves that quirk. C010 must freeze a command-level golden before deciding the public behavior.
