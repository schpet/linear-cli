# P02B — Bubblewrap filesystem confinement for the Linux parity lane

Follow-up to `P02.md`, closing its blocking gap: the `unshare` lane isolated networking but left host files and pathname Unix sockets visible to every program under test. The plan in `untracked/notebook/2026-09-23-rust-port/P02/bwrap-plan.md` and Claude's accepted critique (`bwrap-claude-feedback.md`) are implemented as described below. Reference identity is unchanged (revision `d4fe6fa7358f018fd1da0c6b96ec2b022247e898`, Deno 2.7.9, binary and lock digests in `rust/parity/baseline.json`); no production `src/**`, GraphQL schema, root `deno.json`/`deno.lock`, case file or expected byte changed. No Docker, no live Linear.

## What was built

- `rust/parity/runner/bwrap.ts` (new) — the confinement wrapper, layered strictly above `engine.ts`, which still knows nothing about binds. `resolveBwrap` locates `/usr/bin/bwrap` or `/bin/bwrap`, requires Bubblewrap ≥ 0.9.0 and fails closed otherwise (checked in the outer runner before staging and again inside the lane). `prepareConfinement` inspects the host once: merged-usr entries for `/bin`, `/sbin`, `/lib`, `/lib64` are reproduced as symlinks with the host's targets (or read-only binds on a non-merged host), and the shared read-only binds are validated: the staged `DENO_DIR` and the pinned compiled reference binary, which is therefore bound for every child including self-check wrappers. `programInvocation` derives the executable, argv and program-owned read-only paths from the `Program` (interpreted: `deno` plus `deno.json`, `deno.lock`, `src/`; executable: the file itself). `validateBindSource` realpaths and stats every source, requires the expected kind (executable bit for programs), and refuses `/proc`, `/dev`, `/sys`, `/tmp`, `/run`, `/var/run`, `/etc`, `/boot`, `/root`, `/usr/local`, the whole trees `/`, `/home`, `/usr`, `/var`, `/var/tmp`, `/opt`, `/srv`, `/mnt`, `/media`, and (in `planConfinement`) anything inside the case root or that would shadow the system tree; the given path is the destination the child sees and the realpath is the source. Case roots must be realpaths under `/var/tmp` and never under `/tmp`; `cwd` and `tmp` must be realpaths inside the case root. Neither cases nor candidate descriptors can declare binds. `bwrapArgs` is pure and produces, in mount order: `--unshare-user --unshare-pid --unshare-uts --hostname linear-parity --uid 1000 --gid 1000 --cap-drop ALL --disable-userns --assert-userns-disabled --die-with-parent --clearenv --setenv …`, `--ro-bind /usr /usr`, `--tmpfs /usr/local --remount-ro /usr/local`, the system symlinks, `--proc /proc --dev /dev`, `--bind <caseRoot> <caseRoot>`, `--bind <caseRoot>/tmp /tmp`, one `--ro-bind` per validated program/shared path, `--remount-ro /` last, `--chdir <cwd>`, `-- <program> …`. No `--new-session`, no `--as-pid-1`, no `--unshare-net` (the lane's network namespace is inherited, so only loopback exists). The child environment is the case's explicit map plus `DENO_NO_UPDATE_CHECK=1`, never inherited; a case declaring a different value is rejected. Bubblewrap also sets `PWD` from `--chdir`, overwriting a case-set value, and the preflight pins both additions. `runConfined` runs the plan through `runIsolated` (so `setsid`, deadline, output cap, abort and group kill are unchanged) and classifies an exit-1/empty-stdout/`bwrap:` observation as `ConfinementError`, a harness error that aborts the run (exit 2) rather than a candidate mismatch.
- `sandbox.ts` — each case root now has `tmp/` next to `home/`, `config/`, `cwd/` and `bin/`; it is hashed like the rest, so implicit temp writes become `tmp/...` file effects. `treeDigest` produces a stable digest of a whole tree.
- `run.ts` — `RunContext` carries the `Confinement` and a required `sandboxParent`; `executeCase` runs every baseline and candidate through `runConfined`. Self-check wrappers go through the same path unchanged.
- `fs-canary.ts` (new) and `preflight.ts` — `probeConfinement` creates a throwaway sandbox under the lane directory, a non-secret marker, a second-marker path and a listening pathname Unix socket in a lane-private directory that is never bound, plus a symlink from the case cwd to the marker, and runs the filesystem canary through the real wrapper. It fails closed unless the allowed case file reads, `/tmp` and `HOME` write (and land in the case tree), the marker read, second-marker write, symlink read and socket connect are denied, `/`, `/home` and `/usr/local` writes fail read-only, `/usr/local` is empty, `/run`, `/etc`, `/sys` and `/run/user/1000/bus` are absent, `/proc` lists exactly pid 1 (the bwrap reaper) and the canary, `CapEff`/`CapPrm`/`CapBnd` are zero and `NoNewPrivs` is 1, uid/gid are 1000, `unshare -U` fails, hostname is `linear-parity`, cwd and environment keys are exactly the planned ones, the host marker hash is unchanged and nothing new appeared outside the case root. It then runs the pinned compiled reference `--version` through the executable bind set. `runPreflight` runs the existing network canary through the wrapper too and records Bubblewrap path/version, system links, uid/gid/hostname and both canary outputs in the lane record.
- `main.ts` — the outer runner checks for Bubblewrap before staging. The inner runner creates the lane directory with `Deno.makeTempDir({ dir: "/var/tmp" })` (mode 0700), prepares confinement, digests the staged `DENO_DIR` before preflight and after the last child, records `stagedDenoDir` in the report and fails the run if the digest or entry count changed.
- Tests — `bwrap.test.ts` (new, 13 tests): exact argv for a synthetic plan and absence of forbidden flags; bind validation for missing, non-executable, wrong-kind, relative, `/proc`, `/dev`, `/tmp`, `/run`, `/etc`, `/usr/local`, whole-tree paths and a symlink into `/etc`; plan rejection of `/tmp` case roots, `cwd`/`tmp` outside the root, programs inside the root, system shadowing and a harness-constant override; program bind sets for both kinds; the filesystem canary through the real wrapper (outside the lane, no network) plus a negative control where one added bad bind is a `ConfinementError` mentioning `bwrap:`; exact child environment, `/tmp` writes landing in the case `tmp/`, empty `/usr/local` and pid 1 being `bwrap`; the 128+n fold for a `SIGTERM` self-kill; deadline, output cap, abort and normal exit each removing a `setsid`-escaped `sleep` grandchild (verified by scanning host `/proc` for its unique argv token); and `--die-with-parent` verified by `SIGKILL`ing a separate runner process and observing the confined `sleep` vanish. `run.test.ts` now runs its shell programs through the wrapper under `/var/tmp` (the loopback fixture client is a bash `/dev/tcp` script because only `/usr` is visible inside). `sandbox.test.ts` expects `tmp/`. `engine.test.ts` is untouched and stays on the raw spawn path.
- Docs — `rust/PARITY_HARNESS.md` describes the confined lane, the preflight, the harness constant, `tmp/` effects and the signal limitation; `rust/WORK_ITEMS.md` adds the P02B row and notes the P04 process-status requirement.

## Platform facts and limitations

- **Signal exits fold to 128+n.** Bubblewrap 0.9's reaper reports a program killed by signal n as exit code 128+n (measured: `kill -TERM $$` → `{code: 143}`, pinned by a test), and `--json-status-fd` on this build reports the same folded code. The 13 P02 cases assert only codes, so they are compared exactly and remain verified; no case asserting a signal is claimed. **P04 blocker:** exact SIGINT/SIGPIPE/cancellation parity needs an out-of-band process-status capture (a native helper or explicit signal side channel); the generic engine's signal tests stay on the raw spawn path. `--as-pid-1` is not an option: a PID 1 shell ignored SIGTERM in a probe.
- **Identity.** Inside the lane the runner is uid 0 of a user namespace, so without `--uid`/`--cap-drop` the child kept a full capability set (Claude's standalone probe saw zero caps because it ran as uid 1000). The wrapper pins uid/gid 1000 and drops all capabilities; the preflight asserts zero `CapEff/CapPrm/CapBnd`.
- **No `/etc`.** Nothing in the corpus needs it; DNS inside the sandbox fails on the missing `resolv.conf` before it fails on the network namespace. If a later case needs name lookup, user lookup or `/etc/localtime`, add a lane-built minimal `etc/` bound read-only; never bind the host's.
- **Program locations.** Candidates, reference binaries and stage directories under `/tmp`, `/usr/local`, `/etc`, `/run` or the case root are refused at plan time, and `/usr/local` is masked inside the sandbox, so host-installed tools there are invisible to programs under test.
- **Stale lanes.** `/var/tmp` persists across reboots; a `SIGKILL`ed runner can leave a `linear-parity-lane-*` directory behind (removed in `finally` on every normal or aborted exit; none were left after these runs).
- **Diagnostics heuristic.** A candidate that prints exactly a `bwrap:` prefix on stderr, nothing on stdout and exits 1 would be misclassified as a harness error and abort the run loudly; accepted.
- **`docs/deno-permissions.md`** now lists `bwrap` and describes both the outer network namespace and per-child filesystem isolation.
- Memory and disk: no cache copies were needed. The read-only staged `DENO_DIR` bind holds for both Deno forms (Deno falls back to in-memory SQLite when its cache is unwritable), so the SQLite/WAL/SHM copy fallback from the plan was not implemented.

## Independent review

Claude reviewed the uncommitted P02B diff read-only and recommended a local intermediate commit, with two path invariants and several small accuracy fixes. Its findings were resolved as follows:

1. `planConfinement` now rejects a `cwd` or `tmp` whose realpath differs from the declared path. A regression replaces each with a symlink to the lane directory and verifies rejection before Bubblewrap receives a bind source.
2. `loadCases` uses `lstat` so a symlinked cwd fixture source is rejected; a corpus-loading regression covers the case.
3. `expected.exit.signal` is rejected at load time with the explicit P04 status-channel requirement. The comparator continues to report an observed signal against a code expectation as an exit mismatch. The 13 pinned cases need no changes.
4. The harness specification and this record now describe both environment additions: `DENO_NO_UPDATE_CHECK=1` and Bubblewrap's `PWD` derived from `--chdir`.
5. The optional abstract Unix socket probe is deferred. The outer preflight verifies the fresh network namespace has only loopback, and the existing pathname socket probe tests filesystem isolation.
6. `docs/deno-permissions.md` now lists `bwrap` and describes per-child filesystem isolation.

The coordinator also found that missing or malformed denial fields could pass the canary because `String(undefined)` was accepted. The filesystem and network validators now require explicit, recognizable denial strings for every field, including the nested-user-namespace attempt. Focused negative tests reject missing, nonstring, empty, success-marker and unrelated-error values. The full confined lane passed with the actual denial results on this VM.
