# R02B4 production async and transport adapter

R02B4 is a foundation commit after R02B3. It makes the original process transport variables available to a future network action through one closed, redacted startup snapshot, resolves the reviewed direct/additive-CA/exact-loopback policy only on demand, and supplies a lazy current-thread Tokio bridge. It adds no CLI route and performs no credential lookup or live request. C001 will supply the selected typed API key and call the bridge for `auth whoami`.

## Policy and handoff

`TransportEnvInputs` copies only the documented proxy/CA keys from B3's original `ProcessEnvSnapshot`, including Windows original spellings. Empty values count as unset. On Unix, simultaneous nonempty upper/lower spellings conflict. The accepted modes are direct public roots, direct public roots plus a PEM selected by `SSL_CERT_FILE`, or the exact loopback HTTPS CONNECT proxy with `NO_PROXY=127.0.0.1,localhost` (either order), an absolute PEM, and optional identical `DENO_CERT`. Every other nonempty proxy/CA shape gives a typed variable-name-only error when a network action resolves transport. `build_client` alone reads and validates the PEM after credential selection; the same `TransportConfig` can be used by GraphQL and asset transports. The runtime is built only inside `block_on_network`, and its shutdown has a 500 ms bound.

## Dependencies

The production `tokio =1.47.4` dependency now declares its `net` feature explicitly because application code creates an IO runtime. The feature was already enabled transitively by reqwest; no package version or lock resolution changed. A test-only direct dependency on `tokio-rustls =0.26.5` with `default-features=false`, `ring,tls12` drives the private TLS fixture. It was already in `Cargo.lock`; the lockfile adds only the crate's direct dependency entry. `tokio-rustls` is MIT OR Apache-2.0 and declares MSRV 1.71, below the project's Rust 1.93 toolchain. No runtime dependency was added for test TLS. The alternate CA certificate under `tests/graphql/fixtures` is a generated public test certificate; its private key is not tracked.

## Compatibility and open work

R02B4's proxy policy is intentionally narrower than Deno's ambient transport behavior. It rejects nonempty `HTTP_PROXY`/`ALL_PROXY`, lowercase alternatives on Unix, `SSL_CERT_DIR`, `DENO_TLS_CA_STORE`, lone/mismatched `DENO_CERT`, and partial/non-loopback proxy shapes at network construction. A matching `DENO_CERT` plus `SSL_CERT_FILE` is accepted in direct and loopback modes; Rust adds the PEM to public roots. Rust also imposes a 4 MiB PEM cap and accepts symlinked regular PEM files. These differences become observable when C001 supplies a network command; offline routes with valid UTF-8 values remain usable. B1's already documented non-UTF-8 process-value rejection still happens at startup on every route. Deno network behavior under these CA/proxy shapes is inferred from source/runtime behavior, not captured by the offline oracle. The confined runner cannot express lower-case aliases or Unix upper/lower conflicts. Requiring `SSL_CERT_FILE` in proxy mode deliberately excludes a plain CONNECT proxy with public roots. A PEM path replaced by a FIFO between the metadata check and open remains an unclosed race; the pre-open check rejects stable FIFO paths. A panic escaping the network future can bypass the explicit runtime shutdown bound. For multiple invalid transport categories, the current order is conflicts, unsupported keys, DENO_CERT mismatch, CA path, then proxy shape; Windows case-folding retains original names in conflicts/unsupported errors, while other category messages use canonical upper-case names. The existing TLS fixture leaf and CA expire on 2031-09-23 and will need renewal then. The live environment must fit a supported shape before C001 live QA; a broader proxy policy, if needed, is a separate reviewed item.

R02B3's shared debug setting now drives a fixed GraphQL HTTP status/error-count/partial-data summary and a transport source chain. C001 will bind its first public-binary debug goldens. This foundation has no route-level network request or credential selection, so it does not claim command parity or a live workspace pass.
