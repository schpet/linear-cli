# C009G — bounded Git-root probe in the parity runner

Status: reviewed local candidate in an isolated jj workspace; no production command route is implemented by this change. The frozen Deno 2.6.0 reference remains unchanged. This adapter lets `team id` cases run from a disposable nested cwd with a fixed private `git rev-parse --show-toplevel` helper, so Git-root config precedence can be observed without a host Git repository or a general process fixture. The user waived dependency approval pauses; C009G adds no dependency or permission.

The case schema accepts only the paired `gitProbe: "parent-root" | "outside-repo"` and `cwdSubdir: "subdir"` values. Every ordinary case retains an empty private `bin` and its original cwd. Opt-in cases stage a fixed source-owned shell helper at `bin/git`, mode 0500, before file hashing. The helper accepts exactly `rev-parse --show-toplevel`: the parent-root mode prints the physical one-level parent, and outside-repo mode exits 128 with Git's fatal outside-repository stderr. Before the case action, a five-second, 4-KiB-confined execution probe checks exact helper exit, stdout and stderr, so an unexecutable helper is a harness failure rather than a passing config case. The runner uses the nested cwd for both child execution and `{{cwd}}` substitution. Post-run helper type, mode and source-content hash checks complement the content/tree diff, which does not encode chmod-only changes. Candidate views retain both closed fields; no case may provide script text or a path outside its own sandbox.
