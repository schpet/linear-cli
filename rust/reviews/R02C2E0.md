# R02C2E0 — credential startup frozen oracle

This is an evidence and parity-runner slice before Rust credential startup. It does not change the Rust executable or claim a command leaf. The ten cases live in the dedicated `rust/parity/runner/r02c2-frozen-cases/` corpus; they will enter the main Rust candidate corpus with reviewed v3 goldens when R02C2 implements startup. Keeping them separate preserves the existing main candidate gate while the Rust binary still does not load credentials.

## Review and implementation

Claude's initial read-only plan review returned REVISE because the interpreted reference and pinned compiled binary print different module roots in uncaught errors, and the first plan would have treated claimed Rust root cases as green without goldens. A confined one-case run confirmed the different stack URLs. The revised plan received Claude SHIP. `{{referenceModuleUrl}}` now resolves per program only in expected output: the interpreted program's own workspace via `toFileUrl`, or `/tmp/deno-compile-reference-linear` for the pinned compiled binary whose SHA-256 is `a17675c5ab9a0bf5f32f65e5e68112676576972a9979f5a97bc844f6b23e0835` in `rust/parity/baseline.json`. Any other executable with that placeholder errors. Reviewed Rust goldens cannot use it. Case schema also requires `PATH={{bin}}`, so the synthetic keyring cases cannot invoke the host executable. No dependency or lockfile change.

The corpus captures absent and fake inline credentials, an invalid inline default, metadata default and missing executable warnings (plain and color), malformed credentials before help or bad arguments, malformed global config plus credentials, and a leading UTF-8 BOM. It uses private HOME/XDG/APPDATA/PATH and no GraphQL fixture. The compiled Deno and interpreted Deno references passed **10/10** with exact exit, stdout, stderr and file effects, zero candidate failures or baseline drift. The deterministic case/fixture hash bundle (`find rust/parity/runner/r02c2-frozen-cases -type f -print0 | sort -z | xargs -0 sha256sum | sha256sum`) is `4a93496d4ffb3e5720faf1de77c6015b082eb078ba967b7b74952a7335eb8d83`. The staged DENO_DIR remained 11,009 entries with SHA-256 `6cf7fd5d357fa6478ed6cded0bc029022dbd04e1b9c99ad6a6dfda9fd556e56e`. The BOM fixture begins `EF BB BF`; the actual frozen parser rejects it before help. This corrects an earlier source-based assumption in the R02C2 plan. Deno also ignores malformed global config and still reports malformed credentials. The inline invalid default emits no keyring-format warning.

An additional synthetic dotenv plus invalid-default case was deliberately excluded from the exact corpus: two confined executions produced different warning orders. One printed credential warnings before the dotenv warning; another printed the dotenv warning first. Rust's deterministic config-then-credential order is therefore a documented v3 decision, not an exact Deno byte claim. The distinct “No keyring entry” warning requires a fake process trace and remains R02C3/P04 work. No host credential/keyring lookup or live Linear request was made.
