# F01B Rust foundation review

Status: buildable foundation, **not F01 parity**. This change is uncommitted for sequential integration with the F01-A capture work.

## Scope delivered

- One-package edition 2024 Cargo workspace and `linear-cli` 2.6.0 library/binary, locked with the exact Rust 1.93.0 toolchain. Run Cargo from `rust/` so rustup selects this pin.
- Typed `AppErrorKind`, `AppError`, `ExitStatus`, `AppContext`, `run(argv, context)` and separate handled/usage diagnostic paths. The context owns the two environment values used by F01, cwd, stdout/stderr writers, TTY state, and ordered startup diagnostics. Future F02/F03/F04 implementations can supply transport/config/auth without a global singleton.
- All 110 canonical routes are static Rust metadata. The generated 110-variant `Route` enum has an exhaustive action mapping. Aliases resolve at each parent; every unimplemented leaf, completion child, and pending parent action produces a visible nonzero development error. Known root and document bare hints and root short `-V` behavior are implemented from existing evidence.
- `tools/generate_routes.py` validates the frozen P01B inventory and emits the checked-in module. It covers ordered paths, children, aliases, hidden flags, descriptions, usage, arguments definition, all examples (including `linear api`), and ordered local/inherited option flags, descriptions, types, args, defaults, and hidden state. The generator rejects a cardinality/schema change. The Rust inventory contract compares each generated entry against the frozen JSON in order and checks source freshness by regeneration.

## Decisions and dependency record

- Kept parsing as a small route resolver for now. Clap remains a candidate for the F01 parser spike, but no dependency was added before the captured combination/error matrix can settle the architecture. The resolver does not claim unknown-command or option parity.
- Runtime uses only the standard library. `serde_json` is a dev dependency only, resolved by `Cargo.lock` to 1.0.151. The lockfile also contains its transitive dependencies. `thiserror`, clap, and unicode-width remain deferred until the renderer/parser spike shows they are necessary.
- Rust 1.93.0 named toolchain was already installed before edits. `rust-toolchain.toml` pins that exact release. Initial lock creation fetched from crates.io outside the parity lane; later checks used `--locked`. No Docker or live Linear request was made.
- `.gitignore` excludes `rust/target/`. Build outputs were removed from the jj working-copy change with `jj file untrack rust/target`; `jj status` shows no target artifacts. Final Cargo verification used `CARGO_BUILD_JOBS=2` for the small VM.
- Option `default` absent in P01B is represented as JSON `null` in generated metadata. The reconciliation test treats absent and null alike for that one field; help descriptions stay verbatim even when they mention a default.
- F01-A established that `NO_COLOR=""` preserves ANSI on `--version`. The context now disables color only for a nonempty value. A public context/error-writer contract covers unset, empty, and `1`; the version renderer itself remains pending.
- Process argv and environment are read with `args_os`/`vars_os`. Arguments convert fallibly; F01 converts only `NO_COLOR` and `LINEAR_DEBUG` values, rejecting invalid UTF-8 for those relevant inputs while ignoring unrelated non-UTF-8 environment values. A unit repro confirms `JUNK=non-UTF8` does not block the CLI's inputs. F03/F04 will add their own relevant environment keys. Final diagnostic writes are checked; if stderr is unavailable, main returns failure status. This boundary behavior has no oracle parity claim.
- Repeated `AppError::with_context` calls now retain every prefix with the newest wrapper outermost. The Auth suggestion remains intact; a contract tests `Failed to view issue: load credentials: missing key` and the inherited suggestion.
- Application `Validation` is handled with `✗` and status 1. Parser `Usage` is a distinct error kind and status 2 path; its failing-command stdout help awaits the F01 renderer. Handled TTY diagnostics wrap the whole red line and the indented gray suggestion with `\x1b[39m` endings, matching the `@std/fmt/colors` bytes from source inspection. Leaves stop child descent, so positional arguments reach their visible unimplemented action.
- The library forbids unsafe code and denies Clippy `as_conversions`, `unwrap_used`, `expect_used`, `panic`, and `indexing_slicing`. The binary enforces the same lints in non-test builds; its test-only module uses assertion helpers. These rules run under the all-targets Clippy gate.
