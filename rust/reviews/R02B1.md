The standard-library production Git adapter runs exactly `git rev-parse --show-toplevel` in the injected cwd. Production Git inherits the complete original process environment; a doc-hidden test constructor replaces it with a private map and short timeout. The adapter closes stdin and stderr, reads stdout on a separate thread with a 64 KiB cap, and enforces a 30-second production deadline with kill/reap. All spawn errors return the source-compatible no-root `SpawnFailure`; post-spawn failures return typed process, timeout, output-size, UTF-8, and path-shape outcomes without exposing Git output in error messages. Validated output is a single absolute path line; an empty completed result is distinct from a spawn failure.

`ProcessEnvSnapshot` collects only config-relevant environment variables from `vars_os`, preserving empty values and Windows original spelling, and rejects non-UTF-8 relevant names or values. The Git child does not consume this filtered snapshot. Config discovery and dotenv loading now propagate typed Git failures; dotenv failures carry earlier ordered warnings. `SpawnFailure` and nonzero completed results retain their different config and dotenv policies. No TOML parser or credential selection is introduced here.

The stdout reader is detached so a grandchild holding Git's pipe cannot extend CLI startup past the deadline. If that grandchild keeps the pipe open indefinitely, one reader thread can remain blocked for the process lifetime. The standard library child handle cannot revoke a grandchild's inherited descriptor; this limitation is bounded to a Git probe and does not expose output or credentials. Reader-thread creation itself is fallible and mapped to a typed I/O failure after the Git child is killed and reaped.
