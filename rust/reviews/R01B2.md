## Contract and implementation

The Claude-SHIP [R01B microplan](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B-plan.md) assigns 185 ordinary single-value route-local options to B2: 170 strings, 11 numbers and four enum declarations using three type names. This slice registers those options from generated route metadata with namespaced `opt:` IDs, original flags/aliases, required and hidden status, and `ArgAction::Set` so repeats fail. It leaves 23 collected options, five `--bulk` options, six default values and action-level conversion for B3/C. No dependency was added.

The [lexical policy matrix](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B2-policy.md) names the 38 exact `(route, option)` free-text pairs that accept separated hyphen-leading values. Other strings require equals for leading hyphens. Numbers accept finite decimal `f64` forms, including separated `-.5` and `-1e+2`; an unexpected `integer` descriptor is a typed inventory invariant until its semantics are reviewed. Enums use exact case-sensitive generated values. All string values, including the B1 credential workspace selector, now reject empty input. The shadow tests cover every descriptor's empty-value behavior, each numeric descriptor's valid/invalid inputs, all four enum value lists, the exact 38-pair text set, aliases, required values, duplicates, short forms, hidden valued options and boundary cases. The five deferred `bulk` descriptors are skipped only if their exact variadic shape matches the reviewed inventory.

The pinned compiled Deno reference, SHA-256 `a17675c5ab9a0bf5f32f65e5e68112676576972a9979f5a97bc844f6b23e0835`, was directly probed under synthetic HOME/XDG/APPDATA, ignored env file, `NO_COLOR=1` and a dead loopback endpoint. Terminal `--flag=` and separated empty `--flag ''` returned exit 2 with `Missing value` for title, description and team; terminal equals-empty sort and sort-order likewise failed. Per pinned Cliffy source, Deno consumes a following nonempty token after an empty equals suffix for every valued option; direct probes covered title, team and workspace. `issue create --title= foo` proceeded to the action, and `--workspace= issue mine` consumed `issue` before rejecting `mine`. Rust's immediate empty-equals rejection is a deliberate v3 grammar change. Exact argv, exit, stdout and stderr bytes are preserved as base64 in the ignored [empty-value evidence](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B2-empty-probes.json) and [Claude follow-up probes](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B2-claude-probes.json). `rust/compatibility.md` records the migration.

The shadow clap tree currently consumes literal `--help`, `--json` and `--` as a pending free-text value; pending numeric, enum and strict-string values instead return a usage error. The equals spelling `--title=--json` remains available. `--help` after a supplied value displays help, whereas frozen Deno rejects the combination with exit 2. These are tested observations, not a runtime syntax decision: R01C must choose and review flag/delimiter precedence before clap replaces the live parser, and R01H supplies rendered help/error goldens. Clap's `allow_negative_numbers` lookahead rejected separated `-.5` and `-1e+2`, both accepted by the frozen Deno parser. B2 instead allows hyphen-leading tokens on numeric options and applies its finite parser, preserving those spellings while still rejecting flag text as an invalid number. The frozen parser also accepts `Number()` spellings `0x10`, `0b1`, `0o7`, padded and whitespace-only values; Rust's decimal-only choice and migration examples are in the compatibility ledger. Exact six-case Deno negative evidence is in the ignored [negative-value probe artifact](/home/exedev/workspace/linear-cli/untracked/notebook/2026-09-24-riir-state/breaking-v3/R01B2-negative-probes.json); the nine follow-up probes cover empty-equals, number, help and attached short forms. R01C will need to reconcile its planned post-parse required-option checks with B2's clap-required declarations before cutover.
