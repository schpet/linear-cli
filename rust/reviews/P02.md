## What was built

`rust/parity/runner/` is a byte-exact subprocess parity runner started with `deno task parity -- --reference <workspace> --reference-binary <binary> [--candidate <descriptor.json>] [--self-check] [--report <file>] [--filter <id>] [--require-complete] [--propose <dir>]`. Machine paths stay on the command line, as in P01.

- `schema.ts` — strict Valibot schemas. A case declares id, manifest route, reason, exact argv, stdin bytes, cwd fixture, a complete explicit environment, declared placeholder substitutions, timeout, output cap, optional loopback fixture script, expected exit or signal, expected stdout and stderr bytes, expected file effects, and `deviation: null`. Unknown keys fail. Byte fields are `{utf8}` or `{base64}` objects. `graphql`, `pty`, `terminal`, `clock`, `keyring` and `processes` are rejected with P03/P04 guidance. The environment must contain `HOME`, `XDG_CONFIG_HOME`, `APPDATA`, `PATH` and `DENO_DIR`; `HOME`/config/`DENO_DIR` must be the sandbox and staged-cache placeholders; `LINEAR_API_KEY` must start with `lin_api_fake`; no value may resemble a real Linear credential; `TMPDIR`/`TMP`/`TEMP` are forbidden (see observations). A fixture case must declare `fixturePort`, and `fixturePort` requires a fixture. Candidate descriptors need an absolute program path or reference workspace plus an explicit route list (or the literal `every-manifest-route`).
- `engine.ts` — spawns through `setsid` so the child is its own session and process group, with `clearEnv` and only the case environment, piped stdin written then closed, stdout and stderr drained concurrently against a byte cap, a hard deadline, and `SIGKILL` to the negative group id on deadline, cap, abort or exception. Drains are cancelled after a grace period so an escaped pipe holder cannot hang the runner. Results distinguish `timedOut` from `truncated` and report signal exits as signals.
- `sandbox.ts` — a fresh temp root per run with `home/`, `config/`, `cwd/` (fixture copy) and an empty `bin/` as the child's entire `PATH`; the tree is hashed before and after (files, directories, symlinks) and the exact effect set is compared.
- `fixture-server.ts` — loopback `Deno.serve` on an ephemeral port serving scripted responses in order, recording method, path, Authorization, User-Agent and body, and answering unscripted requests with 500. `compare.ts` fails on request count, path or Authorization drift. This is deliberately not P03's schema-validated GraphQL execution.
- `program.ts` — the interpreted oracle is exactly `deno run --cached-only --frozen --allow-all --quiet --config <reference>/deno.json <reference>/src/main.ts …`; no other flags exist in the code path, and `program.test.ts` pins the array.
- `stage.ts` — before entering the lane, `deno install --frozen --config <reference>/deno.json --entrypoint <reference>/src/main.ts` populates a dedicated `DENO_DIR` under `<cache home>/linear-parity/stage/<lock-hash-prefix>/deno` (about 110 MB, reused when the marker matches the lock hash, Deno version and workspace; `--restage` rebuilds). Every child receives that path explicitly; the host `DENO_DIR`/`HOME` are never inherited.
- `lane.ts` and `preflight.ts` — the outer runner verifies the pinned identity, loads and validates the corpus and candidate, stages, then re-executes itself as `unshare --user --map-root-user --net --pid --fork --mount-proc deno run --cached-only --frozen --allow-all --quiet --config rust/parity/deno.json rust/parity/runner/main.ts --inside-namespace …`. Inside, the runner (PID 1) runs `ip link set lo up` and then fails closed unless: the runner and a child Deno canary see only `lo` interfaces; the runner's uid map is a user-namespace mapping; the child connects over loopback to the runner and gets a reply; child TCP to `1.1.1.1:443` fails with `NetworkUnreachable`; child DNS for `api.linear.app` and a child `fetch` of `https://api.linear.app/graphql` fail promptly. Kernel, `unshare --version`, `max_user_namespaces`, uid/gid maps, link names and Deno version are recorded in the report. There is no host-network fallback.
- `run.ts` — for each case the baseline (interpreted reference) runs first; any mismatch is `baseline-drift` and the candidate is not consulted. Otherwise, if the descriptor does not list the route the result is `not-implemented` and the candidate program is never invoked; else the candidate runs and is `pass` or `fail`. Mismatch details are sanitized (sandbox and staged-cache paths replaced) and report only lengths, hashes and short escaped excerpts.
- `self-check.ts` — identical-executable sanity (candidate = the same interpreted reference) plus twelve deliberately broken candidates generated as shell wrappers inside the lane.
- `main.ts` — argument parsing, report writing, `--propose` (writes observations to a directory for authoring; it never edits cases), SIGINT/SIGTERM abort that kills the running child group, and lane sandbox cleanup in `finally`.

The corpus (`rust/parity/runner/cases/*.json`, 13 cases) covers `--version` with and without `NO_COLOR`, root/`issue mine`/`api` help, unknown command, unknown option, an invalid custom-type option (all exit 2 with help on stdout and the Cliffy error on stderr, ANSI preserved), `api` without credentials and without a query (exit 1, handled failures), and three loopback smoke cases for `linear api '{ viewer { id } }'` with `LINEAR_API_KEY=lin_api_fake`: a 200 printed as compact JSON with no trailing newline, a 401 body echoed to stderr with a newline and exit 1, and a 200 whose body and expected stdout carry `{{fixturePort}}` (the substitution control). Each fixture case asserts exactly one request on `/graphql` carrying the fake key. Expected bytes were captured through `--propose`, then checked against the reference source (`src/commands/api.ts` output framing and error paths, Cliffy usage-error handling) before being written into the cases; the runner never updates expectations.

## Integration

- Root `deno.json`: `tasks.parity`, `tasks.parity:test`, and `test.exclude: ["rust/"]`. Nothing else changed; `src/**`, `graphql/**` and root `deno.lock` are untouched (hash above).
- `rust/parity/deno.json` declares only `@std/assert`, `@std/encoding`, `@std/fs`, `@std/path` and `valibot`, mirrors the root formatting options, and uses its own `rust/parity/deno.lock`. The feedback asked for the root lockfile, but a non-workspace config that points `lock` at the root file makes Deno 2.7.9 rewrite and prune that file (observed: root `deno.lock` shrank to 62 lines on the first `deno check`; it was restored). Making `rust/parity` a workspace member would also rewrite the root lockfile. The dedicated lockfile was therefore derived without network by copying the root `deno.lock` into `rust/parity/deno.lock` and running `deno check --config rust/parity/deno.json` over the runner and tests, which prunes it to the harness graph while keeping the root's resolved versions and integrity hashes (`@std/path@1.1.4`, `valibot@1.3.1`, …). `deno test --frozen` and `deno check --frozen` under that lockfile pass, so it is complete.
- P01 `verifySourceBinding` now requires an empty `jj diff` for `src`, `deno.lock` and `graphql` only, then compares root `deno.json` structurally with `jj file show -r <reference> deno.json`, deleting exactly the approved `parity`/`parity:test` task strings and `test: {exclude: ["rust/"]}` before demanding identical JSON (key order included). `verify.test.ts` proves mutated `version`, `imports`, `tasks.test`, `unstable`, an extra task, a changed parity task string, an extra exclude entry, an extra `test` key and a new top-level key all fail, while the approved additions pass, and runs the real binding against the working copy.
- `docs/deno-permissions.md` documents the two tasks and the parity config.
- `rust/reviews/P01.md` records the corrected test command.

## Observations and decisions

- The compiled Deno binary resolves its embedded module root from the temp directory: with `TMPDIR` set to a fresh directory it fails with `Module not found: …/deno-compile-reference-linear/src/main.ts` and creates `deno-compile-reference-linear/.deno_compile_node_modules` there. With `TMPDIR` unset it runs and writes nothing. Cases therefore must not set `TMPDIR` (schema-enforced), and P04/G02 should keep this in mind for native lanes.
- Rust's spawn resolves the program against the child's `PATH`, which is the case's empty sandbox `bin/`, so `setsid` is resolved to an absolute path by the engine.
- `deno task parity -- …` forwards the leading `--` separator to the script in Deno 2.7.9; the outer parser accepts that position and strips it before namespace relay.
- The canary child runs with `--no-config --no-lock` so it neither discovers the reference config nor touches a lockfile; it has no imports.
- The lane leaves the private mount namespace implied by `--mount-proc` alone; sandboxes live under a per-run `linear-parity-lane-*` temp directory removed in `finally`, and the compiled binary was verified not to write to `/tmp` when `TMPDIR` is unset. Further filesystem confinement is under separate review.
- The reference's `src/__codegen__` output already exists in the frozen workspace; nothing regenerates it.
- P01's verifier ran `jj` with a bare `PATH` environment. jj snapshots the working copy on every command and, without `HOME`, cannot read the user's git config or global excludes, so those runs added globally ignored files (`untracked/**`, `.claude/settings.local.json`) to `@`. `verify.ts` now passes `HOME`/`XDG_CONFIG_HOME` through to every `jj` call, and the working copy was restored with `jj file untrack`. The coordinator should confirm `jj status` lists only the P02 files before committing.

## Independent Claude diff review and fixes

Claude's independent review identified five concrete gaps: descendants could survive or hold pipes after the direct child exited; symlink effects disagreed with the schema and FIFO reads could hang; new TypeScript contained type assertions; case and runner inputs were looser than intended; and reports exposed raw fake Authorization values. The follow-up diff fixes these without changing the pinned Deno reference.

- The engine kills the whole process group on deadline, cap, abort, exception and normal completion, including when its leader has already exited. A drain grace timer remains armed after leader exit. Regression tests cover a descendant retaining stdout/stderr past the leader's exit and one redirecting both pipes before the leader exits.
- Symlink effects carry the exact target, file SHA-256 is limited to created/modified files, and unsupported special entries throw before `readFile`; a FIFO regression test verifies prompt rejection. The case schema requires scripted response count to equal `expectedRequests`.
- All `as` assertions/casts in the new P02 runner and tests were removed. Parsed JSON is narrowed or passed through the existing schema parser. Placeholder parsing rejects malformed opening tokens while allowing literal JSON closing braces. `--` is accepted only at the start of the outer task arguments and stripped before namespace relay. A candidate descriptor's executable must already exist, be a regular file and be executable before cases run. Internal `--deno-dir` and `--staged-reused` are rejected by the outer parser.
- Fixture summaries and reports record Authorization match booleans rather than header values. Root parity task and parity test task both use `--frozen`; P01's root-config binding approves only those exact strings. `rust/PARITY_HARNESS.md` now describes the `unshare` lane used on this VM.

The first post-fix run reported 38 passing registrations because `run.test.ts` imported a helper from `schema.test.ts`, registering its six tests twice. The helper now lives in `test-fixtures.ts`, leaving 34 distinct tests after two new regressions. The full legacy suite was already run before these follow-up edits and was not repeated because they only touch the parity harness.
