## Implementation and public contracts

The parser consumes registered positional descriptors in order after option parsing. Missing later required values name the next descriptor, optional descriptors may be absent, and variadic descriptors consume the remaining command tokens. Leftover values on non-variadic routes become one space-joined `Too many arguments` diagnostic. Registered variadic option descriptors now take the remaining nonempty option values, including flag-looking tokens, stopping at the first empty token. The existing zero-input plural diagnostic, standalone-help exemption, zero-positional route behavior, parent unknown-command handling, and literal `--` separation remain in place. A required positional variadic with no value follows the same missing-argument path, but no registered route exposes this case; it is source-derived and untested against the binary reference.

Public binary tests assert exit 2 and exact observed stderr for malformed zero, partial, and surplus forms across one-, two-, and three-required-argument routes, plus the required/optional link route, help precedence, literal `--`, zero-positional auth route, and the empty-token bulk edge. They compare stdout to **Rust-rendered short no-color help**, because these cases were not added to frozen fixtures. Parser tests confirm accepted exact, optional, and nonempty variadic forms reach `ParseOutcome::Action` without dispatching a live operation. Variadic option parser tests assert all values, including flag-like tokens, are retained; public binary tests assert that the same argv reaches Rust's visible unimplemented-action boundary (its stderr differs from the Deno action's no-key error by design). A parent-help regression checks the existing parent route.
