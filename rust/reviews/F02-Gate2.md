## Transport as built (`transport.rs`)

- **Shared client factory.** `build_client(&TransportConfig) -> Result<Client, TransportBuildError>` is Gate 1's `GraphQlTransport::new` body, extracted verbatim: `http1_only`, `Policy::none`, `referer(false)`, `timeout(deadline)`, `retry::never`, then `no_proxy()` for `Direct` or `proxy(Proxy::https(url).no_proxy(NoProxy::from_string(LOOPBACK_NO_PROXY)))` for `HttpsConnect { bypass_loopback: true }`, then `add_root_certificate` for every certificate of `load_pem_bundle`. `GraphQlTransport::new` and the new `AssetHttpTransport::new` both call it, so a loopback GraphQL POST and a fixed-host GET built from one `TransportConfig` carry identical proxy and CA settings. The body collector and network classifier were likewise hoisted into private `collect`/`classify_network` returning a private `ExchangeFailure { ResponseTooLarge, Timeout, Network }` that each transport maps onto its own failure enum with its own origin; `send_bytes` behaves as before (same variants, same messages, same deadline wrapping).
- **Confined-lane adapter.** `ConfinedEnvValues { https_proxy, http_proxy, all_proxy, no_proxy, ssl_cert_file }` holds raw `Option<String>` values a caller has read; the module still never reads the environment. `ConfinedTransportEnv::parse` rejects, in order: `HTTP_PROXY` or `ALL_PROXY` present (`Unexpected`, because `HttpsConnect` never proxies plain `http` and a silently ignored value is refused instead), `HTTPS_PROXY` missing/empty/not a loopback `http` origin (`Missing`/`Empty`/`Proxy(ProxyUrlError)`), `NO_PROXY` missing/empty or not exactly the two entries `127.0.0.1` and `localhost` in any order (`NoProxy(Blank|NotLoopback|Duplicate|NotConfinedPolicy)`, entries named by index only), `SSL_CERT_FILE` missing/empty/relative (`Missing`/`Empty`/`CaPathNotAbsolute`). `into_config(deadline, cap)` yields `HttpsConnect { bypass_loopback: true }` + `PublicRootsPlusPem(path)`; the PEM's existence, regular-file kind, framing and DER are checked by `build_client` before any request, exactly as in Gate 1. There is no fallback to defaults and no unbounded mode. This is not F03 environment discovery.
- **Asset URL type.** `AssetHost::{Uploads, Public}` (`uploads.linear.app`, `public.linear.app`; only `Uploads` is `authenticated()`). `AssetUrl::parse` requires `https`, one of the two hosts (normalized by the parser), no explicit port, no credentials, no fragment; `Display`/`Debug` print only `https://<host>`. Any other host is `HostNotAllowed` before any request.
- **Redirect resolver (pure).** `resolve_redirect(current, Option<&HeaderValue>)` accepts only a visible-ASCII `Location` that starts with `/`, not `//`, contains no backslash (the URL parser would turn `/\host` into a scheme-relative reference), joins against the current URL, re-validates through `AssetUrl` and requires the same fixed host; `MissingLocation`, `MalformedLocation`, `NotOriginRelative`, `CrossOrigin` carry no text. `follow_redirect(current, redirects_so_far, status, location)` treats only 301/302/303/307/308 as redirects, bounds them by `MAX_REDIRECTS = 2` (`TooManyRedirects { limit }`), and returns any other status as the final response.
- **`AssetHttpTransport::new(api_key, config)` / `get(&AssetUrl)`.** Per request: `User-Agent: schpet-linear-cli/2.6.0` always, `Authorization` only when the host in flight is `Uploads`, re-decided on every hop; no default headers on the client. Each hop goes through the shared `collect` (Content-Length pre-check, chunked read, cap) and the whole multi-hop exchange runs under one `tokio::time::timeout(deadline)` (reqwest's own per-request timeout is the same value). Returns `AssetResponse { requests, response: RawHttpResponse }` with exact status, headers and body bytes for whatever the final status is; the caller decides what a non-200 means. Failures: `Redirect { origin, request, rejection }`, `ResponseTooLarge { origin, status, limit }`, `Timeout { origin, deadline }`, `Network { origin, phase, source }`; every `reqwest::Error` enters through `SanitizedReqwestError::new` (`without_url()`), `Display` prints only the origin plus the innermost source message, derived `Debug` prints the same plus `RawHttpResponse`'s size-only `Debug`.

Not implemented on purpose: Markdown rewriting, image cache files, any `document` command, signed-upload PUT, the broad F07 asset API, `From<AssetFailure> for AppError`, TLS/proxy-specific `NetworkPhase` variants (a TLS failure classifies as `Connect` from `is_connect()`; see the public-roots control).

## Probe (`examples/f02b_fixed_host_probe.rs`)

Argument: exactly one scenario name from a compiled enum (`both`, `redirect`, `cap-below-body`, `wrong-auth`, `wrong-path`, `extra-get`, `public-roots-only`, `wrong-proxy-port`, `graphql-wrong-variables`, `direct-egress`, `third-host`); anything else exits 2 with usage on stderr and nothing on stdout. Environment: the probe reads `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY`, `SSL_CERT_FILE` into `ConfinedEnvValues` and parses them strictly **before** any scenario override, then `LINEAR_API_KEY` (through `ApiKey::new`) and `LINEAR_GRAPHQL_ENDPOINT` (through `EndpointUrl::parse`, additionally required to be plain `http` on a loopback host). Compiled-in fake values only: the two fixed-host URLs with `?token=fake`, an undeclared path, a third-host URL, the expected fake bytes, the wrong fake key `lin_api_fake_wrong`, and the closed proxy `http://127.0.0.1:1`. Limits: 10 s deadline, 1 MiB cap (8 bytes for `cap-below-body`). Scenario overrides change only the typed config in memory (`CaMode::PublicRoots`, `ProxyMode::HttpsConnect` to the closed port, `ProxyMode::Direct`); the runner-owned case environment is never edited.

Output contract (stdout, one line per step, first failure ends the run with exit 1): `graphql ok teams=<n>` / `graphql failed: <Display>`; `<label> ok requests=<n> bytes=<len>` after an internal byte-for-byte comparison with the compiled fake bytes, `<label> body differs (<len> bytes)`, `<label> status <code>` for a non-200 final response, `<label> failed: <Display>`; `third-host rejected: <AssetUrlError>`. The `direct-egress` scenario prints `connection to <origin> failed (root message elided)` for a `Network` failure because the lane's DNS/egress denial text is an OS/confinement fact, not a transport contract. No line can contain the key, a path, a query or the CA path.

Both transports in every scenario are built from the same `TransportConfig`; the GraphQL POST reaches `http://127.0.0.1` because `Proxy::https` never intercepts a plain-`http` URL (scheme-based non-interception). It proves nothing about `NO_PROXY` bypass; `NO_PROXY` is validated by the adapter tests only.

## Deviations from the reviewed microplan, and why

1. **No "missing auth" or "public leaks Authorization" probe scenario.** `AssetHttpTransport` decides `Authorization` from the host type and takes a mandatory `ApiKey`; the shared transport cannot express either misbehaviour, and adding a test-only override or a second reqwest path would have been exactly the second network path the task forbids. The auth control is `wrong-auth` (fixture side) and the positive `both` case, whose consumed public step forbids `Authorization`, is the proof that no key leaked; the matcher's forbidden-header branch itself is covered by C2's `http-assets.test.ts`.
2. **`direct-egress` prints phase and origin only.** Its OS/DNS text under the namespace is confinement evidence, not a transport contract, and cannot be pinned byte-exactly before the lane runs.
3. **`MAX_REDIRECTS = 2`** (three requests at most) rather than an unspecified "finite" count; C2's redirect case needs one.
4. **`User-Agent` is pinned on asset steps** through `requiredHeaders` in the dedicated cases (C2's document cases do not require it); the transport sends it on every GET.
5. **Every case declares a fixed-host step, including `graphql-wrong-variables`**, because the probe requires the runner-owned proxy/CA values in every scenario and `run.ts` injects them only when a fixed-host step exists; the unreached step is part of that control's expected fixture mismatch.
6. **The typed adapter also refuses `HTTP_PROXY`/`ALL_PROXY`** (the plan asked only for the three runner keys); the runner sets neither, and refusing them keeps the "plain-http is never proxied" fact explicit rather than silently true.

## Limits, failure boundaries and what is not claimed

- Scheme-based non-interception only: the loopback GraphQL POST never consults `NO_PROXY`; no claim about HTTPS-loopback bypass.
- No HTTPS GraphQL POST through CONNECT (C2's fixed-host contract is GET-only).
