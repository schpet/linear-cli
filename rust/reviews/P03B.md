# P03B: serial GraphQL fixture execution

This slice connects the frozen P03A GraphQL case contract to a fresh loopback server and record state for each program execution. P02 raw `fixtureServer` cases still use their original server and comparison path. Ordered GraphQL steps are supported; concurrent lanes and asset steps fail before the child starts and remain P03C work.

The server requires POST to the declared path, JSON content type, exact fake Authorization and pinned `schpet-linear-cli/2.6.0` User-Agent, optional named headers, a strict JSON envelope, and the expected presence or absence of `variables`. The P03A matcher checks the selected operation and variable provenance. Normal responses execute against the pinned SDL. A resolver demands own-property presence for every selected schema field, validates scalar/enum/list/non-null/abstract values, and lets graphql-js project aliases, fragments, directives, and introspection. GraphQL errors retain declared status, data, paths, locations, and extensions; transport overrides retain declared bytes. Every bad request or invalid fixture response records a bounded fixture issue and returns deterministic HTTP 500.

Records are cloned per execution. Explicit put/delete effects check prior values and commit atomically. `success:false` on an executed, schema-typed mutation payload or resolved composite field suppresses ordinary data-response effects, including an aliased or unselected `success` field and a payload selecting only `__typename`; scalar JSON contents are opaque. Ordinary mutation effects also require at least one root mutation field to execute, so a statically skipped root cannot change state. GraphQL-error effects require explicit `partialEffects:true`, while non-error responses reject that bit. Final records, consumed steps, request count, and request issues are checked independently of exact child stdout, stderr, exit, and file effects.

## Fixture-format delta for review

P03B adds one narrowly scoped response-data notation to the frozen P03A examples: an exact one-key object `{ "$record": "Record:id" }` in a **composite GraphQL source position** refers to a record in `initialRecords` or one declared by an effect. The case loader rejects mixed/malformed composite references and names absent from initial or declared put records; the resolver checks actual existence at request time before a successful response and emits a fixture mismatch/HTTP 500 if an earlier effect did not create the record. It resolves at the root object and at object/interface/union field sources, including list elements. It does not interpret `$record` inside `JSON` or `JSONObject` scalar payloads; `{ "$record": "literal" }` remains literal JSON there. This notation is exercised by the named-record mutation and scalar-literal tests. No arbitrary object key or alternate sentinel form is recognized. The notation is also recorded in `rust/PARITY_HARNESS.md`.
