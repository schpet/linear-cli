# P04B1 review record: native all-PTY helper proof

P04B1 adds an opt-in `all-pty` branch to the authenticated status helper and a repeatable native canary. The TypeScript runner still invokes only the existing `parity-status/2` pipe modes. It cannot select or parse the new `parity-status/3` PTY mode. This slice proves the native topology and cleanup in actual Bubblewrap confinement; it does **not** claim CLI PTY parity or accept PTY case JSON. P04B2 owns the TypeScript status channel, live engine, strict case schema and corpus.

The helper opens master and slave inside bwrap's private `/dev` after HELLO/ACK. The target child alone calls `setsid`, acquires the controlling tty, becomes its foreground process group, and maps the slave to FD 0/1/2 before `execve`. The helper parent relays raw master bytes to stdout and uses nonblocking `waitpid` plus a 20 ms `poll` wake. Each master drain pass is limited to 64 KiB, so a busy writer cannot trap the helper in one read loop before reap, action handling or the two-second post-exit grace. RESULT is authenticated at exact target reap with final termios class/flags and observed window size. EIO/EOF seen before reap is provisional: the helper reads again after reap before treating it as final. An authenticated DONE with the final relay total follows only proven post-reap EIO. A descendant retaining the slave instead produces RETAINED after the grace and exits with the target's own code, even when that code is 122. Child setup and exec errors are distinct `/3` RESULT variants and helper failures. The pre-reap POLLHUP path disables master polling for that pass, avoiding a tight spin; the canary checks a slave close/reopen and a continuous post-exit writer.

Helper stdin accepts canonical `ACTION <index> raw|cooked <key-hex>\n` lines. It rejects malformed size/action fields, embedded NUL, high-byte fragments, concatenated keys and out-of-order indexes. It accepts one control/ASCII byte, one valid Unicode scalar, or one of the bounded cursor/delete escapes. After positive exec confirmation, each action requires a matching termios gate, a bounded **zero-byte** drain to EAGAIN, then a second matching gate before the key write. A complete write produces authenticated `APPLIED <nonce> <index> <cumulative-relayed-bytes>`; a wrong state or target EOF leaves the action unapplied. A short, blocked or failed master write produces typed INPUT_FAILURE without ACK or helper stderr. The gate–drain–gate order makes the ACK count exact for programs that finish rendering before entering the gated state, including the frozen Cliffy prompt. Bytes written while already gated remain a residual race that B2's determinism gate must detect.

The helper's 64 MiB native relay guard produces authenticated LIMIT without helper stderr, then exits 126 and relies on bwrap PID-namespace teardown. LIMIT may occur before target reap, with no RESULT, or after target reap, following one RESULT. B2 must keep every effective runner output cap strictly below that guard so ordinary floods are classified by the runner first. A runner-initiated kill can preempt RESULT/DONE/RETAINED; B2 must classify from its own kill reason, and only require terminal frames and empty helper stderr on runs it did not kill. A target exit during a partial control line likewise yields no APPLIED and can still complete with RESULT/DONE.

The successful `/3` grammar is HELLO/ACK, zero or more APPLIED frames, one `RESULT <nonce> <identity> <targetPid> exited <code>|signaled <number> <name>|signaled-unlisted <number> pty <requestedColumns> <requestedRows> <relayedAtReap> <raw|cooked|other> <iflag> <oflag> <lflag> <observedColumns> <observedRows>`, then exactly one `DONE <nonce> <finalRelayed>` or `RETAINED <nonce> <relayedAtGrace>`, then EOF. `signaled-unlisted` is the typed target result for Linux signals 32–64, including real-time signals; it retains target-consistent outer status and never writes a helper diagnostic. Setup/exec failures use the distinct `RESULT ... setup-failed|exec-failed <errno>` form and still require DONE after EIO. `LIMIT <nonce> <relayed>` is terminal either before RESULT or after RESULT but before DONE/RETAINED; both sequences exit 126 without helper stderr. `INPUT_FAILURE <nonce> <index> <relayed> <written> <errno>` is terminal only before RESULT, for an incomplete master key write (`written=-1` on a failed write, with errno; nonnegative short writes use errno 0), and also exits 126 without helper stderr. The target-controlled no-stderr audit covers relay overflow → LIMIT, boundary EIO → unapplied action then RESULT/DONE, short/blocked key write → INPUT_FAILURE, real-time signal → signaled-unlisted RESULT/DONE, and target exit during a partial action line → RESULT/DONE. A closed runner stdout pipe produces a quiet helper exit; B2 distinguishes that using its own kill reason.

The explicit cooked termios baseline is ICRNL input, OPOST|ONLCR output, CS8|CREAD control, ECHO|ICANON|ISIG|IEXTEN local, zero input/output speed, VINTR 3, VQUIT 28, VERASE 127, VKILL 21, VEOF 4, VMIN 1, VTIME 0, with all other control bytes zero. The child canary checks the full state before toggling raw. The legacy drain, closed-at-start and close-after-bytes branches and their `/2` wire grammar are unchanged; `build-status-helper.ts` pins the changed C source so normal A2 staging rebuilds and verifies it.
