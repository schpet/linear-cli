# C030A — typed Rust `milestone list`

The Rust CLI resolves `--project` with the C024A shared resolver (UUID pass-through, project URL slug-only lookup, exact name then slug, ambiguity and not-found suggestions, URL workspace checks before credentials), then walks a separate typed Cynic `GetProjectMilestones` query. The operation name, nullable `$first: Int` and `$after: String` declarations and selection order match `src/commands/milestone/milestone-list.ts`. Every page sends `first: 100`; page one omits `after`, and later pages send the previous `endCursor`. Only the root `project` is optional; every nested non-null field stays strict.

`commands::milestone_list::run_with(original, project_id, fetch, json, columns, color)` owns paging, sorting and rendering behind an injectable fetch. It uses the shared strict paginator: a null root on any page is `Project not found: <raw --project>` with no suggestion and discards earlier pages; a null or empty cursor with `hasNextPage` is the source's `Linear reported more milestones but returned no pagination cursor` / `Retry the command.` without a page suffix; a repeated cursor stops with `Linear repeated a milestone pagination cursor on page N`. Fetch errors keep their own message (not the paginator's `page N failed`). Milestones are stably sorted by `targetDate` with the root collator, null and empty dates last, then by name; `sortOrder` does not affect order. JSON is the selected `{nodes,pageInfo}` connection in source key order with the final page's `pageInfo`, ECMAScript number text for `sortOrder`, two-space indent and a final LF. Text uses the shared `display`, `table::underlined_header` and `truncate_js` helpers to reproduce the source column rules, UTF-16 slicing and 120-column pipe width.

The app route applies `Failed to fetch milestones` exactly once: preparation and resolver errors gain it in the dispatcher, and every `run_with` error already carries it. The spinner follows `template_view`: frame 0 is written before config, credential and URL preparation, frames tick through resolver lookups and all pages, and the line is cleared before any output or error. It is suppressed by `--json`, a non-terminal stdout or any `NO_COLOR` value, including empty; the header underline instead uses `stdout_tty && !no_color()`, so it remains on for an empty `NO_COLOR`.

No dependency was added.
