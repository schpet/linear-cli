# C024F2 — terminal Markdown renderer and pager foundation

This foundation supplies reusable TTY Markdown rendering and pager delivery for the future `project view` action. It does not register the route, fetch data, or transform non-TTY Markdown. `PAGER` is captured only from the process environment; `NO_COLOR` already has absent, empty, and nonempty states. A combined render/deliver entry accepts injectable terminal dimensions, process runner, hostname, and stdout writer. An unavailable size uses 80 rendering columns and the source's >50-line paging threshold. Either zero terminal dimension is also treated as unavailable. A non-UTF-8 process `PAGER` stays in a typed lossless state at startup, so unrelated help and version commands work; it becomes a Validation error only when paging would use it.

The measured spike rejected `pulldown-cmark-mdcat = 2.17.0` because it needs Rust 1.95 while this repository pins Rust 1.93. The selected `pulldown-cmark = 0.13.4` has default features disabled. `gethostname = 1.1.0` supplies the local image URL host in production. The custom renderer has a 64-level nesting cap and sanitizes document control characters before writing terminal escape sequences. Its scratch comparison matched 84/102 fixture/mode pairs against charmd. The remaining 18 are reviewed v3 format differences: ordered lists starting at 0, control characters becoming U+FFFD, CRLF hard breaks becoming LF, and tables without outer pipes rendering as tables. No byte-exact TTY parity is claimed. `rust/compatibility.md` records the user-facing boundary. The public boundary test confirms 64 nested quotes render and 65 fail with a Validation error. The raw non-TTY action path will remain unaffected.

Pager commands are executable plus argv, never shell strings. The primary `PAGER` preserves empty versus whitespace-only values; Unix fallbacks are `less -R -X`, `more`, `cat`, and Windows fallbacks are `more`, `less -R -X`. Native Windows execution, including whether `more.com` resolves as `more`, has not been qualified. Fallback omission compares the exact failed executable name. Pager stdout and stderr are inherited from the terminal, while stdin receives the renderer's exact bytes. The output adapter is flushed before spawn. Nonzero or signal exit, spawn/write/wait errors, and an early stdin close fall through. A successful pager does not add a newline; all-fail direct output adds one LF using the console broken-pipe policy.

Public contract tests cover structure and thematic-rule width at 40/120, Unicode, links, image formatting, local-path encoding for space/percent/hash/ question mark and Unicode, repeated template placeholders, `NO_COLOR` states, pure thresholds at rows 0/1/2, adapter normalization of zero size to unknown, exactly 50 versus 51 lines with size unavailable, command boundaries, fallback and all-fail behavior, and process-only `PAGER`. Unix fake-child contracts check exact stdin/argv/environment, early quit with a 1 MiB input, exit 17, and SIGTERM. This foundation's tests are synthetic; the C024 action must run route-level frozen parity and PTY QA. A reproducible bounded PTY probe asserts both terminal output markers; its script and summary are at `untracked/notebook/workspace-consolidation/c024f2-pty-probe.py` and `untracked/notebook/workspace-consolidation/c024f2-pty-evidence.txt`.
