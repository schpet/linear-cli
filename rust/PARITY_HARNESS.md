# Parity harness specification

This is an implementation specification; the harness does not exist yet. Build it in `rust/parity/` before porting production commands. Its first acceptance test is the pinned interpreted Deno CLI against its compiled Deno executable (plus identical-executable sanity checks); the second uses deliberately broken candidate executables to prove that discrepancies fail.

## Oracle and coverage

Pin reference revision `d4fe6fa7358f018fd1da0c6b96ec2b022247e898`, Deno toolchain (CI currently 2.7.9), `deno.lock`, schema digest, build command and binary digest in `baseline.json`. Materialize the reference in an isolated jj workspace outside the implementation tree; never build the oracle from the changing checkout. Warm dependencies/codegen in a build step, then deny external networking during tests. `--baseline` and `--candidate` are harness paths, not new application flags. Rust output binary remains `linear`; use an absolute path to keep the installed Deno CLI available.

Export Cliffy's runtime command graph under an isolated environment, including hidden/generated commands, arguments, aliases, globals, local flags, defaults, multiplicity, conflicts, help/version and executable parent actions. Reconcile this against the static inventory: 86 source-registered leaves, 20 parent actions. Source-only helpers such as `auth-status.ts` and `project-description.ts` are not automatically public commands. Capture actual alias behavior and completion shells, not assumptions from filenames.

Track each route in `manifest.json`: canonical route, aliases, source path, work-item ID, fixtures, modes (text/json/tty as supported), effect classes, offline status, QA status, live status and explicit exclusions. Also map each named GraphQL operation/fragment and its source to the commands exercising it, so shared helper operations are not missed. A `--json` fixture is mandatory only where the source exposes it (`issue mine` does not). New routes/flags or missing entries fail inventory verification. Each source option needs a meaningful case, plus high-risk combinations; do not generate a meaningless Cartesian product.

A minimum baseline before command implementation contains all help/default/alias routes and at least a success and failure case for every behavioral command (local-only commands use meaningful local scenarios). Read commands add empty/missing/multipage where applicable; writes add cancellation and exact effects. Deep cases can grow with each reviewed micro-plan, but a command cannot be declared implemented with help-only coverage.

## Runner and fixtures

Use Deno and the existing GraphQL/Valibot/standard-library dependencies initially. This makes fixture capture independent of the new Rust runtime and avoids waiting on the Rust rewrite to test it. Keep all new tests under `rust/parity`; register a dedicated `deno task parity` script entry in implementation, and use the repository's `deno task test` for Deno test suites. In P02 set root `deno.json` `test.exclude` to include `rust/`; the parity task runs `rust/parity/runner/main.ts` directly, including its self-check mode, so it is independent of Deno test discovery. Verify legacy targeted task invocations still work. See [Deno test configuration](https://docs.deno.com/runtime/reference/cli/test/). Deno remains a development oracle, never a Rust runtime dependency.

Each case is a schema-checked manifest with:

- Stable ID, owning route/item and reason this case matters.
- Exact argv, stdin bytes or PTY keystrokes, terminal size, cwd fixture, environment allowlist, virtual clock if needed, timeout, fixture files and config/credential format.
- Expected GraphQL operation sequences with explicitly declared concurrency groups, semantic document/argument expectations, full variables including omitted/null distinctions, response/status/error/delay schedule, upload/download bodies and headers.
- Expected stdout, stderr, exit or signal, filesystem changes, child process invocations and final fake service state.
- Comparison rules and any specific reviewed deviation ID.

Run each program in a freshly cloned sandbox with independent service state, never in sequence against the same mutable fake database. Clear inherited secrets, `LINEAR_*`, `GH_*`, `GITHUB_*`, proxy and credential-helper configuration. Assign HOME/XDG_CONFIG_HOME/APPDATA and temporary directories **only in each child's explicit environment map**; do not repurpose the coordinator's shell HOME. Include only trusted executable paths and fake credentials. `LINEAR_IGNORE_ENV_FILE=1` is the normal lane; dedicated cases enable isolated `.env` fixtures.

A localhost GraphQL server supports ordered reads, writes, cursor pages, partial errors, auth/rate-limit failures, delays and malformed responses. Use the existing graphql-js dependency (`validate` and `execute` with fixture resolvers) against the pinned schema for normal cases, with explicit HTTP/body overrides for malformed-response tests. Use schema-driven projection/validation to ensure returned fixtures contain required selected fields, including union `__typename` and nullable nested objects. Existing `MockLinearServer` fixtures often omit fields; migrate their data after validating it. Match **all** variables and assert request counts. Unexpected requests and unused required expectations fail the test independently of the CLI result.

Compare query semantics using the existing GraphQL AST library: tolerate query/fragment/variable renaming, whitespace and equivalent fragment expansion; resolve variables for comparison, retaining omission, defaults and explicit null. Preserve aliases, selection coverage, arguments, directives, root operation kind and mutation field order. Fail broadened filters and missing selections. Permit narrowly declared extra `__typename` selections needed by Cynic. Do not require identical query strings or operation names. Cases may declare an unordered group of independent reads, such as one viewer request per credential in `auth list`; match the exact multiset including full variables, fake auth identity and counts. Independent bulk mutations may form an explicit concurrency group only when each resource's causal sequence and exact final effects are still asserted. Dependent operations, pages and mutation fields remain ordered. Do not broadly ignore ordering or duplicate writes to make a test pass.

Upload/download fixtures test signed URL headers, public/private choice, MIME/size constraints, link creation and binary bytes, private-download auth scoping and redirects. Use test-only transport URL routing for the fixed private host when localhost endpoint injection is insufficient; keep credential decisions based on the original URL. Verify those paths against the normal binary in a controlled network integration lane too.

Fake `git`, `jj`, `gh`, credential tools, editor, pager and browser executables record argv/cwd/stdin/selected env and return scripted outputs. Supplement process traces with disposable real Git/jj repositories, including dirty, immutable, bookmarked, existing-branch, missing-tool, failure and cancellation cases. Native keyrings require an injected backend in a **test-only driver**, followed by real OS compatibility tests; PATH stubs cannot intercept Windows FFI.

## Determinism and comparison policy

| Surface             | Comparison                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exit/status         | Exact per baseline or explicitly approved behavior; distinguish usage errors (currently exit 2), handled failures (1), propagated child codes (`issue commits`), cancellation, SIGINT and broken pipe.                                                                                                                                                                                                                                                                                                                                                                                                |
| Plain stdout/stderr | Exact bytes by default at fixed width/locale; stdout and stderr remain separate. Framework help cosmetics require explicit decisions, never a blanket ignore.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| JSON                | Compare stdout bytes by default, including indentation, object-key order, number text and trailing newline; parse values as an additional diagnostic for types, GraphQL names/nesting, null versus absent, array order, connection wrappers and pageInfo. Any accepted formatting difference must be a case-specific reviewed deviation. Reject extra chatter, fields or envelopes. Independently assert output framing: `api` emits compact JSON with no trailing newline when piped, unlike most `--json` commands. Cover numeric coercion/precision/exponent cases without silently losing values. |
| GraphQL/HTTP        | Semantic document equivalence plus full effective variables, declared causal order/concurrency groups and exact count, Authorization scoping, User-Agent/version and effect state.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Files               | Compare relative paths, contents, modes where meaningful, atomic replacement and no unintended writes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Subprocesses        | Compare intent and arguments; identify permitted implementation differences explicitly. Verify actual final repository state when using real VCS fixtures.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Interactive output  | Record prompts, answers, terminal state and cancellation. Deterministic PTY traces for colors, OSC-8/Markdown hyperlinks, width, Unicode, spinner cleanup and paging; only spinner frame timing may be case-scoped. Include the Deno CSS-style table headers, true-color state colors, locale date formatting and Unicode glyph widths.                                                                                                                                                                                                                                                               |
| Markdown/SDL        | Exact public text by default. If library formatting differs, compare parsed structure as additional evidence and require an approved formatting deviation; never normalize prose, links or literal code away.                                                                                                                                                                                                                                                                                                                                                                                         |

Set TZ/locale/terminal dimensions. For clock-sensitive tests, run a Deno subprocess bootstrap that installs the existing fake timer before importing the reference CLI; use a Rust test-driver executable invoking the same dispatch with an injected `Clock`. Both must parse real argv and exercise startup; ordinary release binaries also run fixed-date and smoke cases. No new clock/test-backend flags or environment switches ship in the normal binary. Retain the existing public `LINEAR_GRAPHQL_ENDPOINT` override as part of compatibility. Check reference bootstrap output against the normal oracle on clock-independent cases.

Normalizers are named, case-scoped and reviewable. They may substitute sandbox roots, assigned ports and intentionally volatile timestamps. Every normalizer has a negative control proving it still catches a meaningful change. Never sort arrays, erase nulls, trim all text, ignore stderr, strip all ANSI in TTY cases, or redact real credentials after accidentally recording them: use fake secrets from the start.

P02 establishes one authoritative **Linux** capture lane: prebuild/cache the reference, dependencies, candidate and test image, then run the entire fixture server and child-process runner together inside a pinned Docker container with `--network none`, loopback IPv4 URLs and no host socket/credential mounts. A Linux network namespace is an alternative only after the same denial test passes. Prove a child cannot connect to a non-fixture address and record the negative-control result; endpoint injection alone is not confinement. Docker's [none network driver](https://docs.docker.com/engine/network/drivers/none/) retains loopback. If no local container runtime is available, use the designated Linux CI runner/VM; installing a new tool follows the dependency/tool policy. P05–P10 use this Linux lane and do not wait for macOS/Windows confinement. A missing authoritative lane blocks capture explicitly.

P04 builds the Linux PTY adapter first. G02 owns native macOS/Windows qualification and platform-specific fixture capture using disposable OS VMs with outbound-deny firewall rules allowing loopback, validated by the same connection canary. Missing native capabilities are platform blockers, not a reason to weaken the Linux gate or claim parity on that OS. Native keyring tests use isolated OS credential profiles. Build/cache dependencies outside all runtime network restrictions. Shared platform-neutral fixtures can be reused; platform-specific output has separate expectations.

Every invocation has a deadline, bounded output capture, child process group cleanup and fixture cleanup even after panic, timeout or SIGINT. Parallel tests use unique ports/paths/state; mutable scenarios are independent.

## Harness self-tests and reporting

Before production command implementation, prove failures for: changed exit code, output moved to stderr, changed JSON key/order/number text/newline, null replacing omitted input, unexpected variable, missing page, reordered nodes, extra mutation, false success response, incorrect upload body, unintended file write, credential host leak and unconsumed expected request. Interpreted-Deno versus compiled-Deno and identical-reference runs should pass; a missing Rust command is explicitly `not-implemented`, never a pass or accepted snapshot.

Reports contain baseline and candidate hashes, command manifest hash, selected platform/config mode, pass/fail/not-implemented/blocked counts, and links to small sanitized evidence. A command-level check fails on any selected case failure or missing coverage. Incremental port runs may report remaining unimplemented commands without blocking unrelated commits; the final `--require-complete` run rejects every missing/unimplemented/blocked offline case or unresolved deviation. Never update all snapshots just to make Rust green.

Cases use independently reviewed expectations as well as the reference result. If Deno currently violates a documented invariant, preserve the old observation, mark the case as an explicit deviation proposal, and specify the Rust expected behavior. Strict validation improvements need their own regression case and review disposition. Partial feature parity must remain visible throughout the port.
